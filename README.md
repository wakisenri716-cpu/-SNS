# ジャジバ（観光専用SNS）

観光の情報格差解消と自治体プロモーション支援を目的とした、観光特化型SNSのMVP実装です。企画書の内容に基づき、以下をコア機能として実装しています。

- Instagram/TikTokのリールのような縦スクロール動画フィード（「おすすめ」）。10件ずつ読み込み、下までスクロールすると続きを自動で読み込む（旅行スタイルによる並び替え時は最新100件を一度に表示）
- **リール動画を投稿できるのは自治体アカウント、および自治体に紐づいた企業アカウントのみ**（一般ユーザーは閲覧・いいね・コメントのみ）
- 自治体プロフィール（アクセス方法・宿情報・飲食店・観光情報・OTA外部リンク・投稿一覧）
- 自治体管理ダッシュボード：「投稿」「観光情報」「アクセス方法」「宿情報」「飲食店」のタブに分かれており、「投稿」タブでリール投稿・削除、「観光情報」タブで管轄内の観光スポットを1件ずつ登録・編集・削除できる。ほかに紐づく企業一覧の確認、MaaS起点駅の設定も可能
- 企業管理ダッシュボード（自社が投稿したリールの投稿・編集・削除のみ。自治体プロフィールの編集は不可）
- 投稿の編集：両ダッシュボードの「投稿を編集」から説明文・カテゴリ・場所（場所名と緯度経度）・対応タグを変更できる（動画の差し替えは不可）。緯度経度を両方空にして保存すると、投稿時と同様に場所名から位置を自動設定し直す（Google Maps設定時）。削除は確認ダイアログを経て行う
- コメント：リールの全画面表示でコメントのアイコンを押すと、下からコメント欄が開く（閲覧はだれでも、投稿はログイン時のみ。`GET/POST /api/reels/:id/comments`）。自治体・企業が設定でコメントをオフにしている投稿には書き込めない。コメントは書いた本人と、その投稿を管理する自治体・企業が削除できる（`DELETE /api/reels/:id/comments/:commentId`）
- コメントの通報：ほかの人のコメントは「通報」から理由（スパム・宣伝／誹謗中傷・嫌がらせ／その他）を選んで通報できる（1人1回。`CommentReport` テーブル）。3人から通報されると自動で非表示になり（書いた本人と、その投稿を管理する自治体・企業には「非表示中」として見える）、管理画面の「通報されたコメント」で削除するか、問題なければ「残す」で通報を取り消す（`GET /api/reels/mine/reported-comments`）
- 共有：リールの全画面表示とアクセス画面の「共有」で、その投稿のアクセス画面へのリンクを共有できる（スマホでは端末の共有メニュー、使えない環境ではリンクをコピー）。アイコンだけのボタン（いいね・保存・閉じる等）には読み上げ用の名前を付けている
- お知らせ：自治体・企業アカウントには、自分の投稿へのいいね・コメントがメニューの「お知らせ」に届く（未読数のバッジ付き、スマホではメニューのアイコンに赤い点。`GET /api/notifications`、`backend/src/lib/notifications.ts`）。設定画面の「いいね通知」「コメント通知」をオフにするとその種類は作られない。自分自身の操作では通知せず、いいねの付け外しを繰り返しても1回だけ。コメントが削除されると、そのお知らせも消える。プッシュ通知・メールには未対応で、アプリ内のお知らせのみ。一般ユーザーは投稿しないため、お知らせも通知設定も表示しない
- 旅行者向けのお知らせ：フォローしている自治体・企業が新しく投稿すると、旅行者のお知らせ（スマホは上部のベル、PCは左メニュー）に動画の小さな画像付きで届く（`notifyFollowersOfNewPost`、`backend/src/lib/notifications.ts`）。自治体と企業の両方をフォローしていても1回だけ。設定画面の「フォロー中の新着投稿」でオフにできる（`User.notifyOnNewPost`）
- キーワード検索、ルールベースの「AIレコメンド」。検索では「バリアフリー対応」などの対応タグでも絞り込める（複数選ぶとすべてを満たす投稿のみ。タグだけでも検索可、`GET /api/search?tags=`）。検索結果の投稿をタップするとその投稿のアクセス画面に移動する
- MaaS/OTA連携の土台（下記「外部連携について」参照）
- 初めての人向け：ログインしていない訪問者には、フィード上部に「ジャジバとは」の短い案内と登録への導線を表示（閉じるとその端末では再表示しない）。リンクを共有したときのプレビュー用に、`index.html` に説明文とOGP/Twitterカード（`frontend/public/og-image.png`、1200×630）を設定。OGPのURLは本番ドメイン `https://jaziba.jp/` を前提にしている
- 登録直後のオンボーディング：旅行者が新規登録すると、3ステップ（だれと行くか・好きな場所の種類・バリアフリー／外国語対応）をタップで選ぶ画面（`/welcome`、`frontend/src/pages/OnboardingPage.tsx`）が出て、最初のフィードからその人向けの並びになる。「あとで」で飛ばせ、設定画面の「旅行スタイル」でいつでも変えられる
- リンクのプレビュー：投稿のアクセス画面（`/reels/:id/access`）と自治体ページ（`/municipalities/:id`）のリンクをLINE・X・Facebookなどで共有すると、その投稿の場所名・自治体名と説明文がプレビューに出る。画面はJavaScriptで作られるため、サーバーがこれらのページを返すときだけタイトル・説明・`og:*` を書き換えている（`backend/src/lib/pageMeta.ts`）。プレビュー画像は共通の `og-image.png` のまま
- スマホ対応：タブレット幅（768px）未満では左メニューを隠し、上部バーのメニューアイコンから開くドロワーメニューに切り替わる。画面右側の「しおり」パネルは幅1280px以上でのみ表示されるため、それ未満ではメニューの「しおり」から専用ページ（`/itinerary`）で表示する

## デザイン

SNSとしての使い心地は今どきのアプリに合わせつつ、見た目は新しいロゴ（4つのタイルのモザイク）に揃えています（`frontend/src/index.css` の `@theme`）。ボタン・リンク・選択中の表示などのメインの色はロゴのティール（白い文字が読みやすいよう少し濃くした `jz-accent` = `#0E7F7F`）、文字はロゴの墨色（`jz-ink` = `#1F2A30`）。ロゴのオレンジの丸（`jz-warm` = `#F26B38`）をモチーフにして、いいね、未読・ライブの印、いま開いているメニューの印、見出しの終わりの点、ログイン前の案内カードの「日の出」、スタンプ（朱色寄りの `#C2481C`）に使っています。黄色と青は、AIのボタンやストーリーの輪のグラデーション、ホームの背景の光など飾りだけに使い、文字の背景にはしません。エラー表示は `jz-warm-text`（`#C2481C`）。絵文字は使わず、アイコンはすべて lucide-react の線画。フォントは英数字がロゴと同じ Outfit、日本語が Noto Sans JP（Google Fonts）。 スマホの下のタブバーは「リキッドグラス」（明るいすりガラスに光る縁）で、いまのタブには小さなレンズのような丸がばねのように滑って移動し、タブを切り替えると進んだ向きにページが左右へスライドします（View Transitions。上下のバーは動かない）。ページ読み込み中はロゴの4つのタイルが順に弾むローダー、読み込み中の枠は青緑がかった光が流れます。スポットのページの動画は、映像の色で周りがほんのり光ります（アンビエント）。見出しは和文を詰めて組み（palt）、行の折り返しを整えます（text-wrap: balance / pretty）。動きを減らす設定の端末ではアニメーションを止めます

- **ロゴ**：提供されたロゴキット（形と色の違う4つのタイルを2×2に並べたマークと、Outfit ExtraBold の小文字「jaziba」）。ファイルは `frontend/public/brand/`（`jaziba-logo-light.svg`／`jaziba-logo-dark.svg`＝マーク＋文字、`jaziba-mark.svg`／`jaziba-mark-on-dark.svg`＝マーク単体、`jaziba-app-icon.svg`＝アプリアイコン）。文字はフォントに頼らないようアウトライン化（形はキットのSVGを Outfit 800 で表示したものと同じ）。ダークモードでは白文字・青タイルを明るくした版に切り替わります（`frontend/src/components/JazibaLogo.tsx`）。ファビコンは `frontend/public/favicon.svg`（16px向けに単純化した版）と `icons/favicon-16.png`／`favicon-32.png`、ホーム画面のアイコンは `icons/icon-192.png`／`icon-512.png`／`maskable-512.png`／`apple-touch-icon.png`、リンクのプレビュー画像は `og-image.png`、シェア画像用は `brand/jaziba-logo.png`。ロゴの色は `@theme` に `jz-brand-teal`（#14A3A3）・`jz-brand-orange`（#F26B38）・`jz-brand-yellow`（#F6C343）・`jz-brand-blue`（#3A6EA5）・`jz-brand-blue-light`（#6E9BD1）・`jz-brand-ink`（#1F2A30）として登録しています

- スマホ：上部はすりガラスのバー（ロゴとメニュー）で、下にスクロールすると隠れ、少しでも上に戻すと再表示。下部は画面から浮いたガラス風のタブバー（アイコンのみ。おすすめ・検索・しおり・マイページ、自治体・企業は 管理・インサイト・お知らせ）。メニューは下から出るシート。タブレット以上は左のサイドバー（選択中は太字）
- フィード：「次の旅先を見つけよう」の見出し、フィード内の自治体の丸いアイコン、文字だけのカテゴリ切り替え（スクロールしても上に固定）。投稿は角の丸い大きなカードで、動画の上に投稿者とフォロー（左上）、場所名と都道府県・赤い「行き方」ボタン・音のオン/オフ（下）を重ねる。カードの影は再生中の動画の色に合わせて光る（同じサイトの動画のみ）。カードの下に いいね数・コメント数・共有・「しおり」ボタン、説明文、タグ（#カテゴリ・#対応タグ）、コメント・「5日前」のような投稿日
- 自治体のページ：プロフィール写真・投稿数・フォロワー数・フォローボタンを上に並べ、その下のタブ（投稿・観光情報・アクセス方法・宿情報・飲食店）を切り替える。投稿は正方形の3列グリッド
- 全画面表示：動画の上に背景なしのアイコン（いいね・コメント・保存・共有）を右側に縦に並べ、左下に投稿者・説明・場所・タグと赤い「アクセス」ボタン
- 動き：投稿をタップすると、カードがそのまま広がって全画面表示になる（View Transitions API。閉じると元のカードに戻る。非対応のブラウザでは普通に切り替え）。投稿はスクロールで画面に入るときにふわっと出てくる（CSSのスクロール連動アニメーション）。動画をダブルタップでいいね（大きなハートが出る）、いいね・保存のボタンは押すと弾み、対応するスマホでは軽く振動する。読み込み中はグレーの形がきらっと光るプレースホルダー、ページ切り替えはふわっと表示、コメント欄やメニューは下からスライド。保存すると「しおりに保存しました／しおりを見る」の通知が出る。端末で「視差効果を減らす」を設定している人には動きを止める
- 動画：同時に再生するのは画面に入った1本だけ（全画面を閉じると元の投稿の続きから）。音は最初は消音で、右下（全画面では右上）のボタンで全動画まとめてオン・オフ。全画面では、タップで一時停止・再開、下端に再生位置のバー。フィードでは動画の縦横比に合わせて表示（縦長は4:5、横長は1.91:1まで）
- ダークモード：端末の設定に合わせて自動で切り替わる（設定画面の「表示モード」で ライト／ダーク／端末に合わせる を選べ、メニューからもワンタップで切り替え可能。選択はその端末にのみ保存）。仕組みは `frontend/src/index.css` の `.dark` で、白とグレーの段階・ロゴの墨色を反転させるだけなので、新しい画面も特に何もしなくても対応する。動画の上や赤いボタンの上（`.on-media` など）は白い文字のまま。ロゴはダーク用のSVGに切り替わる。表示前に `index.html` の小さなスクリプトで適用するので、開いた瞬間に白く光らない
- アプリとして使える（PWA）：`frontend/public/manifest.webmanifest` と `frontend/public/sw.js`。スマホのブラウザで「ホーム画面に追加」（Android/Chromeではメニューに「アプリとしてホーム画面に追加」が出る）すると、アドレスバーのないアプリとして起動する。アイコンはロゴキットのアプリアイコン（`frontend/public/icons/`）。一度開いた画面は電波がなくても起動でき（投稿や動画などのデータは通信が必要）、オフラインになると通知が出る。インストールしたアプリでは、お知らせの未読数がアイコンにも表示される（対応端末のみ）。Service Worker は本番ビルドでのみ登録し、開発サーバーではキャッシュしない
- 引っ張って更新：スマホでホームの一番上から下に引っ張ると、赤い丸が大きくなり、離すと最新の投稿を読み込み直す
- デモ投稿の動画（`backend/seed-assets/*.webm`）は実写の映像がないため、各スポット（松本城・上高地 河童橋・五千尺キッチン・上高地帝国ホテル）をイメージしたイラストのアニメーション（縦長720×1280、8秒）。`backend/seed-assets/source/scenes.html` に描画処理があり、`node backend/seed-assets/source/render.mjs matsumotojo kamikochi gosenjaku teikoku` で作り直せる（Playwright と ffmpeg が必要）

## テスト

- バックエンド：`cd backend && npm test`（Node標準のテストランナー）。計算部分（実測の集計で出発地点を2人以上から表示するプライバシー保護、旅行スタイルの並び替え、プランの自動整理、キーワード相談、旅の自動組み立て（日数の読み取り・地域のまとまり・AI応答の後処理）、リンクプレビューの書き換え）の単体テストと、使い捨てのSQLiteデータベースを作って移行・デモデータ投入をしたうえで実際のAPIを呼ぶテスト（登録、旅行者は投稿できないこと、しおり、プラン、AIで旅をつくる、共同編集、スタンプラリーの距離判定と1回限り、AI未設定時の相談・翻訳、フォロワーへの新着お知らせ、プレビュー用タイトル）。開発用のデータベースには触れません
- フロントエンド：`cd frontend && npm test`（カレンダー出力・距離計算・スタンプの日付）
- GitHubにpushすると、`.github/workflows/ci.yml` でリント・テスト・ビルドが自動で走ります

## デモ用シードデータ

`backend/src/seed.ts` は、自治体テーブルが空のときに自動的にデモ自治体「松本市」と、松本市内の観光地・宿・飲食店を紹介するリール4件（松本城・上高地 河童橋・五千尺キッチン・上高地帝国ホテル）を作成します。バックエンド起動時（`npm run dev` / 本番起動どちらも）に自動実行されるので、特別な操作なしにフィードが埋まった状態で確認できます（Renderの無料プランでデータがリセットされた場合も、次回起動時に自動で再投入されます）。

- デモ自治体アカウント：`demo-matsumoto@example.com` / `password123`
- 手動で再シードしたい場合は `cd backend && npm run seed`（既にデータがある場合は何もしません）

### 長野県の全77市町村と主な観光地

長野県の全77市町村（19市・23町・35村）のページと、主な観光地147か所を掲載しています（`backend/src/data/naganoMunicipalities.ts`、`backend/src/lib/municipalityListings.ts`）。起動時に、足りない市町村だけを追加します（何度実行しても重複しません。デモの松本市はそのまま使い、足りない観光地だけ足します）。

- **市町村名・よみ・役所/役場の位置・公式サイト・キャッチフレーズ・地方公共団体コード**：[code4fukui/localgovjp](https://github.com/code4fukui/localgovjp)（CC0）
- **観光地**：ジャジバが一般に知られた情報から作成（名前と短い説明）。そのうち山・湖・峠・高原の32か所の位置は、国土地理院「地名集日本（GAZETTEER OF JAPAN）」を編集して作成しています（[sorami/gazetter-of-japan](https://github.com/sorami/gazetter-of-japan) 経由。1分単位＝約1.5kmのおおよその位置）。出典：国土地理院 https://www.gsi.go.jp/kihonjohochousa/gazetteer.html 。それ以外の観光地は位置を推測で入れず、空のままにしています（自治体が参加後に設定するか、Google Maps 設定時の新規登録で自動取得）
- **まだ参加していない自治体**のページは「未参加」と表示し、情報の出どころと「自治体の方へ：参加・掲載内容の修正のご連絡」（お問い合わせ）を案内します。アカウントはログインできないもの（推測できないランダムなパスワードと、使われない `.invalid` のメールアドレス）にしています。キャッチフレーズは自治体のものとして「」付きで表示します
- **ジャジバ編集部の紹介投稿**：未参加の76市町村それぞれに、観光地ごとの紹介投稿（観光地がない16町村は町の紹介を1件）、計157件を作っています。自治体が投稿したように見せないため、投稿には `Reel.editorial` の印があり、フィード・全画面・詳細画面に「ジャジバ編集部の紹介・映像はイメージ」と表示します。ストーリーには出しません。説明文は観光地の説明そのもので、位置は観光地に位置があるときだけ付けます（地図・しおり・AIで旅をつくるにも使われます）。実際の映像はないため、動画は種類別のイメージ映像10本（温泉・寺社・城跡/史跡・宿場町・湖・渓谷/滝・高原・山・博物館/美術館・町。`backend/seed-assets/theme-*.webm`、`seed-assets/source/scenes.html` で描画）を、同じ種類の投稿で共有しています。どの映像になるかは観光地の名前・説明から決めます（`themeOf`）。紹介投稿がまだない未参加の自治体にだけ作り、自治体が参加して `listing` を外したあとは追加しません
- 役所・役場の位置を、アクセスプランナー（アクセス方法）の起点に使います（起点駅を設定している自治体は起点駅）
- 「エリアから探す」で参加している自治体を先に並べ、市町村名・よみで絞り込めます。検索はよみ（「ながのし」など）でもヒットします
- 自治体が参加を申し込んだときは、運営側で既存の掲載ページをその自治体のアカウントに引き継ぐ想定です（`listing` を外し、ログイン情報を設定。フォロワーはそのまま）

### 全国の自治体ページ（非公式）

長野県以外も含め、全国の市町村と東京23区（1,741。政令指定都市の区は市にまとめています）のページを、起動時に「未参加」のページとして作ります（`backend/src/data/japanMunicipalities.ts`、`syncNationwide` in `backend/src/lib/municipalityListings.ts`）。出典は上と同じ [code4fukui/localgovjp](https://github.com/code4fukui/localgovjp)（CC0）で、市町村名・よみ・役所の位置・公式サイト・キャッチフレーズだけを載せます。観光地や紹介投稿は作りません（事実を作らないため）。地方公共団体コードで重複を防ぎ、すでにあるページ（長野県・参加済みの自治体）はそのまま使います。初回の起動で約1,660件を一度に作り、2回目以降は何もしません。アカウントは長野県の未参加ページと同じくログインできないものです。管理者サイトの「ユーザー」や人数には数えません（「非公式ページ」で絞り込めます）。自治体一覧（`GET /api/municipalities`）は件数が多いので、一覧に必要な項目だけを gzip で返します。

2. Renderダッシュボードで **New + → Blueprint** を選択し、このリポジトリ（`claude/tourism-sns-planning-643nty` ブランチ）を指定する
3. `render.yaml` が自動検出されるので、そのまま **Apply** してデプロイを実行する（ビルドには数分かかります）
4. デプロイ完了後に発行されるURL（`https://<サービス名>.onrender.com`）でブラウザからアクセスできます

Blueprintが使えない場合は、**New + → Web Service** で同じリポジトリを選び、以下を手動設定しても同じ内容になります。

- Build Command: `bash render-build.sh`
- Start Command: `node backend/dist/index.js`
- 環境変数：`NODE_ENV=production`, `DATABASE_URL=file:./dev.db`, `UPLOAD_DIR=./uploads`, `JWT_SECRET=<ランダムな文字列>`

**注意（無料プランの制約）**：Renderの無料プランはディスクが永続化されないため、再デプロイやスリープ復帰のたびにSQLiteのデータ（登録した自治体・投稿したリール動画ファイル）はリセットされます。デモ・検証用途として利用し、本番運用する場合はPostgreSQL（データ）＋S3等（動画ファイル）への切り替えを推奨します。

## データモデル（Prisma / backend/prisma/schema.prisma）

- `User`：一般ユーザー / 自治体担当者 / 企業担当者共通のアカウント（`role` で区別：`USER` | `MUNICIPALITY` | `COMPANY`）
- `Municipality`：自治体プロフィール（`User` と1:1）。アクセス方法・宿・飲食店・OTAリンクを保持
- `TourismSpot`：自治体管轄内の観光スポット1件分（`Municipality` に多対1）。名前と説明を持ち、自治体が管理画面からいくつでも登録・編集・削除できる（旧・単一の`tourismInfo`フリーテキストを置き換えたもの）
- `Company`：自治体に紐づく企業アカウント（`User` と1:1、`Municipality` に多対1）。企業は自己登録時に既存の自治体を選んで紐づける
- `Reel`：自治体名義で表示されるリール動画。`companyId` が設定されていれば、その自治体に紐づく企業が投稿したもの
- `Like` / `Comment`：一般ユーザーによるリールへのいいね・コメント
- `Trip` / `TripItem`：旅行者の旅（しおり）と、その旅に入れた投稿（順番・滞在時間）。1つの投稿を複数の旅に入れられる。`SavedReel` は「どれかの旅に入っている」目印として連動（自分の旅と参加した旅のどちらでも）
- `TripMember`：旅に招待されて参加した人（共同編集）。`Trip.inviteToken` は招待リンクの合言葉
- `TripPhoto`：旅のアルバムの写真（追加した人・撮影日時・近くの場所）
- `TripTransport`：旅の乗る便（旅行者が入力した便名・時刻・のりば・座席など）
- `Passkey`：パスキー（WebAuthn）の公開鍵・使用回数。顔や指紋の情報は含まれません
- `Municipality` の `kana`・`websiteUrl`・`lgCode`（地方公共団体コード）・`officeLat/Lng`（役所・役場の位置）・`listing`（未参加の掲載ページ）：公開データから作った市町村ページ用

## 権限モデル

- リール投稿は `role: MUNICIPALITY` と `role: COMPANY` のアカウントのみ許可（`backend/src/middleware/auth.ts` の `requireRole`）
- **自治体アカウント**：自分の自治体名義の投稿を全て（紐づく企業が投稿したものも含む）編集・削除でき、自治体プロフィール（アクセス・宿・飲食店・観光情報・OTAリンク）も編集できる
- **企業アカウント**：自社が投稿したリールのみ編集・削除できる。自治体プロフィールの編集は不可
- 一般ユーザーはリール閲覧・いいね・コメントのみ可能
- 企業アカウントは自己登録時に既存の自治体をプルダウンから選んで紐づけます。**自治体側の承認ステップはないため、既存の自治体名を選べば誰でもその自治体名義の投稿権限を持つ企業アカウントを作成できます**。実運用では自治体による承認フローや招待制への変更を推奨します。

## 外部連携について（重要）

企画書ではMaaS（交通情報連携）とOTA（宿・航空券予約）連携が構想されていますが、実際の外部API契約・APIキーがない状態のため、本実装では以下の方針で「差し替え可能な形」にしています。

- **OTA連携**（`backend/src/services/otaProvider.ts`）：じゃらん/楽天トラベル/Booking.com等への外部検索リンクを自動生成して自治体プロフィールに表示します。自治体側で実際の提携リンクに上書きすることも可能です（プロフィール編集画面）。実際のOTA APIと契約できた場合は、この関数を実APIコールに差し替えるだけで組み込めます。
- **MaaS連携**（`backend/src/services/maasProvider.ts`）：リールに紐づく場所情報までの、自治体の「起点駅」からの推定所要時間を表示します。`GOOGLE_MAPS_API_KEY` が設定されていれば **Google Maps Platform の実API**（Geocoding + Directions）で実際の距離・所要時間を計算し、未設定時や計算失敗時は自動的に「モックデータ」（決定的な仮の所要時間）にフォールバックします。モック使用時は画面上に必ず「交通情報は仮データ」と表示されるので、ユーザーはどちらのデータか判別できます。設定方法・既知の制約は次の「Google Maps連携のセットアップ」を参照してください。
- 決済機能（宿泊予約や広告出稿の決済）は未実装です。実装には決済代行事業者との契約が必要なため、現段階ではスコープ外としています。

### Google Maps連携のセットアップ（MaaS機能の実データ化）

MaaS機能を実際の地図・経路データで動かすには、Google Maps Platform の **Geocoding API**・**Directions API**・**Static Maps API** を有効化したAPIキーが必要です（Static Mapsはリールのアクセスページで経路のプレビュー画像を表示するために使います）。キーがない状態でもアプリは正常に動作します（自動的にモックデータ・地図なし表示にフォールバックします）。

1. [Google Cloud Console](https://console.cloud.google.com/) にアクセスし、Googleアカウントでログインしてプロジェクトを新規作成する（既存プロジェクトでも可）
2. 請求先アカウント（クレジットカード登録）を設定する。Google Maps Platformは毎月 $200 分の無料クレジットがあり、このアプリの検証用途であれば通常無料枠内に収まります
3. 左メニュー「APIとサービス → ライブラリ」から以下の3つを検索して有効化する
   - **Geocoding API**（地名・住所 → 緯度経度への変換）
   - **Directions API**（2地点間の距離・所要時間の取得）
   - **Static Maps API**（経路プレビュー画像の生成）
4. 「APIとサービス → 認証情報」→「認証情報を作成」→「APIキー」でキーを発行する
5. 発行したキーを選択し、「APIの制限」で上記3つのAPI（Geocoding API, Directions API, Static Maps API）のみに制限する（不要な課金・悪用防止のため必須）。「アプリケーションの制限」は、サーバーサイドからのみ呼び出すキーなので「なし」のままで問題ありません
6. 発行されたキーをバックエンドの環境変数 `GOOGLE_MAPS_API_KEY` に設定する
   - ローカル開発: `backend/.env` に `GOOGLE_MAPS_API_KEY=<発行されたキー>` を追記
   - Render: ダッシュボードの対象サービス → Environment → `GOOGLE_MAPS_API_KEY` を追加

**セキュリティ上の注意**：このキーはバックエンド（サーバー側）でのみ使用し、フロントエンドのコードや `VITE_` 系の環境変数には絶対に含めないでください。フロントエンドに含めるとキーが公開され、第三者に不正利用（高額請求）されるおそれがあります。

設定後、自治体アカウントの管理画面（`/dashboard`）で「MaaS（交通案内）起点駅」欄に最寄り駅・バス停名を入力すると、その地点を起点としてリールの位置情報までの推定所要時間が計算されるようになります。未入力の場合や、キー未設定・API呼び出し失敗時は自動的にモックデータが使われます。

**既知の制約（重要）**：Google MapsのDirections/Routes APIは、`mode=transit`（電車・バスの乗換案内）について日本国内の経路データを一般的なAPIキーには提供していません（検証の結果、京都・東京・大阪の主要駅間で一貫して`ZERO_RESULTS`となることを確認済み。Googleマップアプリ自体が表示する日本の乗換案内は、この公開APIとは別のデータ提携によるものです）。そのため本実装では、実際の乗換時間の代わりに、起点駅からの**徒歩または車移動の実測距離・所要時間**（`backend/src/services/googleMaps.ts` の `getRouteEstimate`：3km以内は徒歩、それ以上は車移動で計算）を使用しています。正確な「電車で何分・何線」といった乗換案内が必要な場合は、駅すぱあとAPI（ヴァル研究所）やNAVITIME APIなど、日本の乗換案内に特化した外部APIへの切り替えを検討してください（`maasProvider.ts` の `getTransitSuggestion` を差し替えるだけで組み込める設計です）。

### AIに旅を相談（AIコンシェルジュ）

ホームと検索画面の「AIに旅を相談」から、「家族で雪景色を見たい」「カップルでおいしいそば」のように、行きたい旅を文章や音声（マイクボタン。ブラウザの音声認識を使用し、対応ブラウザでのみ表示）で伝えると、ジャジバの投稿から合いそうな場所を選び、理由と「行き方」「しおり」ボタン付きで表示します（`POST /api/concierge`、`backend/src/services/concierge.ts`、画面は `frontend/src/components/ConciergeSheet.tsx`）。検索画面の検索欄にも音声入力を付けています。

- **AIモード**：バックエンドに `ANTHROPIC_API_KEY` を設定すると、Claude（標準は `claude-sonnet-5-5`、`CLAUDE_MODEL` で変更可。構造化出力でJSONを返す）が投稿の中から最大5件を選び、一言の理由と返事を書きます。選べる投稿IDはスキーマで限定しているので、実在しない場所を勧めることはなく、理由も投稿の説明・場所・カテゴリ・タグに書かれていることだけを使うよう指示しています（営業時間・料金・バリアフリー可否などの、投稿に書かれていない事実は付け加えない）。安全上の理由でモデルが回答を断った場合はAnthropicの推奨モデルで自動的にやり直す設定（`fallbacks: "default"`）にしています。1IPあたり10分20回まで
- **キーワードモード**：キーが未設定、または呼び出しに失敗した場合は、カテゴリ・対応タグ・地名のキーワード一致で探します。この場合は画面に「AIは未設定」「キーワードの一致で探しています」と必ず表示し、AIの回答のようには見せません
- キーの設定：ローカルは `backend/.env` に `ANTHROPIC_API_KEY=<キー>`、Renderはサービスの Environment に `ANTHROPIC_API_KEY` を追加（キーは https://console.anthropic.com で発行。Google Mapsのキーと同じく、フロントエンドには絶対に含めない）。利用量に応じてAnthropicの料金がかかります

### 会話モード・自分のAIで続ける

- **会話モード**：「AIに旅を相談」の右上のボタンで、話しかける → 答えとおすすめの場所を読み上げる → また聞き取る、を繰り返す音声の会話になります。聞き取りと読み上げはブラウザの機能（Web Speech API・speechSynthesis）で、音声はジャジバに送りません（`frontend/src/lib/speak.ts`、`useSpeechInput.ts`）
- **自分のAIで続ける**：相談の答えの下と、しおりの下に「ChatGPTで開く」「Claudeで開く」「コピー」「ほかのアプリへ」を出します。会話やしおり（立ち寄り先・時刻・滞在時間）を書き込んだ状態で、利用者自身のChatGPT・Claudeが開きます（`https://chatgpt.com/?q=…`・`https://claude.ai/new?q=…`、`frontend/src/lib/ownAi.ts`）。ジャジバからは何も送らず、ジャジバのAIの回数・料金もかかりません。AIの回数を使い切ったときの続きにも使えます

### 写真で探す（AI）

AIコンシェルジュのカメラボタンから写真を送ると、Claudeが写真の雰囲気（景色の種類・季節・過ごし方）を読み取り、似た体験ができる投稿を選びます（`POST /api/concierge/photo`）。写真は端末で長辺1024pxのJPEGに縮小してから送り（位置情報などの元ファイルの情報は付きません）、その1回の相談にだけ使い、保存しません。選べるのはジャジバに実際にある投稿だけで、写真の場所を特定・断定しないよう指示しています。`ANTHROPIC_API_KEY` が未設定のときはボタンを表示しません（写真にはキーワード検索の代わりがないため）。

### ストーリー

ホーム上部の自治体アイコンをタップすると、その自治体の投稿が全画面で1本ずつ自動再生されます（`frontend/src/components/StoryViewer.tsx`）。上部のバーで何本目か・どこまで再生したかが分かり、右側タップで次、左側タップで前、長押しで一時停止、下にスワイプ（PCはEsc）で閉じます。最後まで見ると次の自治体へ進みます。画面下から「行き方」と自治体のページに移動できます。見た投稿はその端末に記録され（`frontend/src/lib/storiesSeen.ts`、localStorage）、全部見た自治体はアイコンの輪がグレーになって列の後ろに回ります。

### 投稿文の翻訳（AI）

アプリを英語・中国語・韓国語で使っている人には、投稿文の下に「See translation（翻訳を見る）」が出ます。押すとClaudeが投稿文を翻訳し、「Claude（AI）による翻訳」と明記して表示します。「原文を見る」で元の日本語に戻せます（`POST /api/reels/:id/translation`、`backend/src/services/translate.ts`）。一度翻訳した文は `ReelTranslation` テーブルに保存して使い回すので、同じ投稿・同じ言語の翻訳でAPI料金がかかるのは最初の1回だけです。投稿文が編集されると保存済みの翻訳は消え、次に押されたときに訳し直します。`ANTHROPIC_API_KEY` が未設定のときはボタン自体を表示しません。1IPあたり10分60回まで。

### リール（縦スワイプ）

下のメニューの「リール」（`/reels`、`frontend/src/pages/ReelsPage.tsx`）は、投稿を画面いっぱいの縦長動画で1本ずつ上にスワイプして見続ける画面です。最後まで来ると続きを自動で読み込みます。いいね・コメント・保存・共有・「アクセス」は全画面表示と同じです。

### 場所を選ぶ（投稿の位置）

投稿（自治体・企業の新しい投稿と編集、旅行者の写真・動画の提供、提供素材からの投稿）の「場所」に「場所を選ぶ」ボタンがあり、緯度・経度を打たなくても位置を付けられます（`frontend/src/components/PlaceField.tsx`・`PlacePickerSheet.tsx`、`backend/src/routes/places.ts`）。

- **名前で探す（入力中）**：ジャジバの中の場所（観光地、すでに投稿にある場所、全国の駅約9,000、市区町村）から候補を出します（`GET /api/places/search`。外部への問い合わせなし）
- **「検索」ボタン**：地図上のすべての名前のある場所（お寺・城・滝・展望台・山・湖・公園・お店・通りなど）を OpenStreetMap から探します（`osm=1`、`backend/src/services/osmSearch.ts`）。公開の Nominatim サーバーの利用ルール（1秒に1回まで・アプリ名を名乗る・結果をキャッシュ・入力中の自動検索はしない）に合わせ、ボタンを押したときだけ、サーバーから1件ずつ順番に問い合わせ、同じ検索は1週間キャッシュします。混み合ったときや失敗したときも、ジャジバの候補と地図のタップで選べます。別の Nominatim 互換サーバーを使うときは環境変数 `NOMINATIM_URL`。結果には「© OpenStreetMap contributors」を表示します
- **地図で選ぶ**：地図（地図で探すと同じ OpenFreeMap）に出ている名前をタップするとその場所を、ほかの所をタップするとその地点を選びます。現在地ボタンもあります。名前はあとから直せます
- 地図は自分の自治体（旅行者の提供では送り先の自治体）の駅・役所のあたりから始まり、検索もその近くを先に出します（`GET /api/places/home`）
- 選んだ位置は、地図で探す・アクセス・しおり・近くのスポットに使われます。「位置を外す」で位置なしにもできます

### 地図で探す

下のメニューの「地図」（`/map`、`frontend/src/pages/MapPage.tsx`、`GET /api/reels/map`）では、場所が登録された投稿が、赤い縁取りの丸い動画アイコンとして傾けた立体地図の上に並びます。カテゴリで絞り込め、現在地ボタンで自分の周りに移動できます。アイコンを押すと下にカードが出て、動画・「行き方」・「しおり」・全画面表示に進めます。地図は MapLibre GL と OpenFreeMap（OpenStreetMapのデータを使った無料の地図。APIキー不要）で表示し、ダークモードでは暗い地図になります。OpenFreeMap側の都合で地図が出ない場合も、投稿のアイコンとカードは使えます。地図のプログラムは大きいので、地図を開いたときだけ読み込みます。

### AIでプランを作る（しおり）

しおりに2か所以上あると「AIでプランを作る」が出ます（`POST /api/me/trips/:id/plan`、`backend/src/services/tripPlanner.ts`、画面は `frontend/src/components/TripPlanSheet.tsx`）。「ゆっくり回りたい」などの希望を入れて押すと、回る順番・各場所の滞在時間・一言メモ・プランの要約を提案し、見たうえで「このプランにする」を押したときだけしおりに反映します（順番は `PUT /me/trips/:id/order`、滞在時間は `PATCH /me/trips/:id/items/:reelId`）。

- `ANTHROPIC_API_KEY` がある場合はClaudeが作ります。メモは投稿に書かれている内容と一般的な助言だけにし、営業時間・料金・予約などの書かれていない事実は書かないよう指示しています
- キーが未設定・失敗時は、移動距離が短くなる順に並べ替えるだけの自動整理になり（宿があれば最後にし、宿から逆向きに近い順でたどる）、滞在時間は変えません。画面にもそう表示します

### AIで旅をつくる（しおり）

しおりの一覧（`/itinerary`）の「AIで旅をつくる」で、「2泊3日で長野、温泉とお城」のように書く（または話す）だけで、ジャジバの投稿から旅を丸ごと組み立てます（`POST /api/me/trips/compose`、`backend/src/services/tripComposer.ts`、画面は `frontend/src/components/TripComposerSheet.tsx`。`/itinerary?compose=1` で直接開けます）。位置情報のある最新80件から、行き先・回る順番・滞在時間・旅の名前を提案し、「1日目」「2日目」に分けて表示します。日の区切りはしおりと同じ決まり（最後以外の宿で1泊）で数えます。提案を見て場所を外したり名前を変えたりしてから「この旅をつくる」を押したときだけ、旅が作られます（`POST /api/me/trips` に `items` を付けて一度に作成）。作ったあとはふつうのしおりとして並び替え・共同編集などができます。

- ANTHROPIC_API_KEY があるときは Claude が組み立てます。選べるのは渡した投稿だけで（出力の形式でIDを制限）、理由は各投稿の説明文・場所・カテゴリなどに書かれていることだけにもとづきます。営業時間・料金など、データにないことは書かせません
- キーがない、またはAIの呼び出しに失敗したときは、「AIに旅を相談」と同じキーワードの一致で投稿を選び、いちばん合う投稿から近い範囲（日帰り60km・泊まりは150km）だけを距離順につなぎます。泊まりの旅では宿の投稿を各日の終わりに入れ、日帰りでは「温泉」「宿」などと書いたときだけ宿を入れます。画面には「AIが設定されていないため、キーワードの一致と距離で組み立てました（AIは使っていません）」と表示します
- 「2泊3日」「3日間」「日帰り」「3 days」「2 nights」「3天」「2박3일」などから日数を読み取ります（最大7日）。泊まれる場所の投稿が足りず希望より短い行程になった場合は、そう表示します

### スタンプラリー

旅行者は、スポットのアクセス画面の「現地でスタンプを押す」で、その場所の記念スタンプを集められます（`POST /api/reels/:id/visit`、`Visit` テーブル）。ブラウザの位置情報がスポットから1km以内のときだけ押せ、1か所1回・20ポイント（移動時間の記録と同じく試作のポイントで、まだ使い道はありません）。離れているときは「あと約○km」と表示します。集めたスタンプはマイページの「スタンプ帳」に並びます（`GET /api/auth/me/stamps`）。位置はブラウザが報告するものなので、正直な利用を前提にした仕組みで、改ざんを完全に防ぐものではありません。

- **現地スタンプのタグ（NFC・QR）**：自治体・企業は、投稿の編集画面の「現地スタンプのタグ」で、その場所に置くNFCタグやQRコードを作れます（`POST/GET/DELETE /api/reels/:id/checkin-tag`、`Reel.checkinToken`、画面は `frontend/src/components/CheckinTagSection.tsx`）。旅行者がタグにスマホをかざす（QRを読む）と `/c/◯◯` が開き、ログイン済みならその場で振動とともにスタンプが押されます（`POST /api/checkin/:token`、`frontend/src/pages/CheckinPage.tsx`。未ログインなら「ログインしてスタンプを押す」）。電波が弱い山の中や、位置情報がずれやすい屋内でも押せます。NFCタグへの書き込みは Android の Chrome なら画面のボタンから（Web NFC）、ほかの端末では市販のNFCアプリでURLを書き込みます。読み取りは iPhone・Android どちらでもでき、アプリを開いていなくても反応します。スタンプには押し方（`Visit.method`：`gps` か `tag`）を記録します。タグのあるスポットでは、スポット画面のスタンプラリー欄に「この場所には現地スタンプのタグがあります」と出ます（投稿の `hasCheckinTag`。タグのURLそのものは出しません）。URLを知っていれば誰でも開けるので、QRの写真が出回ったときは「作り直す」で古いタグ・QRを無効にできます

### 管理者サイト（運営者用）

運営者だけが使える管理画面が `/admin` にあります（アプリのメニューとは別の画面、`frontend/src/pages/AdminPage.tsx`・`backend/src/routes/admin.ts`）。検索エンジンには載せません（noindex）。

- **入れる人**：サーバーの環境変数 `ADMIN_EMAILS`（カンマ区切り）に書いたメールアドレスのアカウントだけ。アプリからは誰も自分を管理者にできません。そのアカウントでログインすると、メニューに「管理者サイト」が出ます
- **概要**：ユーザー数（旅行者・自治体・企業）、この7日の新規登録、14日間の新規登録のグラフ、有料プランの数とカード払いの月の売上見込み、今月・今日のAI費用（概算）と予算に対する割合・機能ごとの内訳、投稿・コメント・スタンプの数、未対応のお問い合わせ・通報・承認待ちの素材
- **お問い合わせ**：フォームから届いた内容を一覧で見て、「メールで返信」（メールアプリが開きます）、「対応済みにする」
- **ユーザー**：名前・メール・自治体名・企業名で検索。プランを付ける／外す（請求書払いの自治体プロなど。カード払いのプランはStripeで管理）、**利用停止**（理由を記録。その場でログアウトされ、ログインもできなくなります）と解除
- **通報**：通報されたコメントを通報の多い順に。「問題なし」（通報を取り消す）、「コメントを削除」、投稿者の利用停止
- **登録の承認**：自治体・企業が新しく登録すると「承認待ち」になります。承認するまでは、ログインして画面を見ることはできますが、投稿・編集・クーポンやイベントの追加・コメントはできず（`requireRole` がGET以外を止めます）、自治体のページも一覧・検索・プロフィールに出ません。企業もまだ承認されていない自治体には所属できません。管理者サイトでは、担当者・メールアドレス（`.lg.jp` の自治体ドメインかどうか）・同じ名前のページがほかにあるか（なりすましの手がかり）を見て「承認する」「承認しない（理由つき）」を選びます。結果は相手の管理画面に表示され、通知をオンにしていればプッシュ通知も届きます。旅行者は承認なしで使えます。デモなどで承認をなくすときは環境変数 `POSTER_APPROVAL=off`
- **管理者への通知**：承認待ちの登録やお問い合わせが届くと、管理者のアカウントにプッシュ通知が届きます（管理者のアカウントで「設定」→プッシュ通知をオンにしておく。タップで管理者サイトの該当画面へ）
- **提供素材（非公式）**：まだ参加していない自治体（非公式ページ）に旅行者が送った写真・動画は、その自治体ではなく運営が確認します（`GET /api/admin/submissions`、`POST /api/admin/submissions/:id/approve|reject|post`）。承認で提供者に100ポイント、「この素材で投稿する」でジャジバの紹介投稿（`editorial`）としてその自治体のページとフィードに出ます（「提供：◯◯さん」つき）。写真は管理者の端末で縦長の動画にしてから投稿します
- **操作の記録**：管理者サイトで行った操作（だれが・いつ・何を）をすべて記録します（`AdminLog`）

### 有料プラン

基本の機能は無料のまま、`/plans`（メニューの「プラン」、`frontend/src/pages/PlansPage.tsx`）で有料プランを選べます。内容と値段は `backend/src/lib/plans.ts` にまとめています。

| アカウント | フリー | 有料プラン |
| --- | --- | --- |
| 旅行者 | AI 月30回分（1日10回分まで） | **プラス 月480円（税込）**：AI 月300回分（1日50回分まで） |
| 企業・お店 | クーポンを同時に1件まで公開・AI 月30回分 | **ビジネス 月2,000円（税込）**：クーポン50件まで・AI 月300回分 |
| 自治体 | クーポンを同時に3件まで公開・AI 月30回分 | **自治体プロ（お見積り・請求書払い）**：クーポン50件まで・AI 月300回分 |

- **カード払い（プラス・ビジネス）**：Stripe Checkout で支払います（カード番号はジャジバに届きません）。支払いが終わると Stripe からの通知（Webhook、`POST /api/billing/webhook`）でプランが有効になり、画面は反映を待って「有効になりました」と出します。変更・解約・領収書・カードの更新は「プランの管理」（Stripe のカスタマーポータル）。解約しても期間の終わりまで使え、更新の支払いに失敗したときは Stripe が再請求するあいだ7日間はそのまま使えます（`backend/src/routes/billing.ts`）
- **請求書払い（自治体プロなど）**：契約後に運営者が `backend` で `npm run plan:grant -- <メールアドレス> municipalityPro 12`（12か月）を実行して有効にします。外すときは `none`
- **AIチケットをお金で売る機能はあえて作っていません**：前払いのチケットを現金で売ると資金決済法（前払式支払手段）の対象になる可能性があるため、チケットはポイント交換だけ、お金は月額プランでいただく形にしています
- **始めるために運営者がすること**
  1. [Stripe](https://dashboard.stripe.com/) のアカウントを作り、商品「プラス」（月480円・税込）と「ビジネス」（月2,000円・税込）の**定期支払いの価格**を作る（金額は `plans.ts` の表示と同じにする）
  2. Webhook の送り先に `https://<backendのURL>/api/billing/webhook` を登録し、イベント `checkout.session.completed`・`customer.subscription.created`・`customer.subscription.updated`・`customer.subscription.deleted` を選ぶ
  3. Stripe の「カスタマーポータル」を有効にする（解約・カード更新を許可）
  4. Render の backend の環境変数に `STRIPE_SECRET_KEY`・`STRIPE_WEBHOOK_SECRET`・`STRIPE_PRICE_PLUS`・`STRIPE_PRICE_BUSINESS`・`APP_ORIGIN`（フロントのURL）を入れて Manual Deploy
  5. **特定商取引法に基づく表記**（`/legal/commerce`）の事業者名・責任者・所在地・電話番号を `frontend/src/lib/operatorInfo.ts` に記入する（空欄のあいだは「下書き」と表示されます）
- 環境変数が無いあいだは、プランの一覧は見られますが「お支払いの準備中」と表示され、申し込めません

### 宿を探す・予約（楽天トラベル）

場所のアクセスページと、自治体ページの「宿情報」タブで、チェックイン日・泊数・人数を入れると、その近く（半径3km）で**空室のある宿と料金**を楽天トラベルの空室検索APIで調べて表示します（`backend/src/services/rakutenTravel.ts`、`backend/src/routes/stays.ts`、画面は `frontend/src/components/StaySearch.tsx`）。安いプラン順に、朝食・夕食の有無と合計金額、「予約へ」ボタンが並び、**予約・お支払い・キャンセルは楽天トラベルの画面で**行います（ジャジバは予約の当事者になりません。旅行業の登録が要らない形です）。同じ検索は10分間キャッシュします。

- **投稿から予約**：位置のある投稿には「宿」ボタン（フィード・全画面表示）があり、押すとその場所の近くの**実際の宿**（楽天トラベルの簡易検索、日程なしで最安料金・評価）が並び、日程を入れると空室と料金が出て「予約へ」で楽天トラベルの予約画面に進みます（`frontend/src/components/StaySheet.tsx`、`GET /api/stays/near/:reelId`）
- **宿の投稿と楽天トラベルの宿の紐づけ**：カテゴリ「宿泊」の投稿は、すぐ近く（600m以内）に同じ名前の宿が楽天トラベルにあれば自動で紐づき（あいまいなときは紐づけません。`backend/src/lib/hotelMatch.ts`）、投稿のボタンが「予約」になってその宿が一番上に出ます。投稿の編集画面の「楽天トラベルの宿と紐づける」で、投稿者（または管理者）が近く1km以内の宿から選び直すこともできます（`Reel.rakutenHotelNo`）
- 使うには [楽天ウェブサービス](https://webservice.rakuten.co.jp/) でアプリを登録し、Render の環境変数に `RAKUTEN_APP_ID`（アプリID）と `RAKUTEN_ACCESS_KEY`（アクセスキー）を入れて Manual Deploy
- `RAKUTEN_AFFILIATE_ID`（楽天アフィリエイトID）も入れると、予約リンクがアフィリエイトリンクになり、予約されるとジャジバに紹介料が入ります。そのときは画面に「［PR］」の表示が出ます（ステルスマーケティング規制への対応）
- 楽天の規約に合わせて「Supported by Rakuten Developers」の表示を出しています
- キーが無いあいだは、空室は出さず（作り物のデータは出しません）「地図で近くの宿を探す」を案内します

### 地元の交通情報（自治体・企業 → アクセスページ）

コミュニティバス・乗合タクシー・宿の送迎・季節運行など、自治体のホームページや紙の資料にしか載っていない交通情報を、自治体（管理画面の「アクセス方法」タブ）と企業（管理画面）が追加できます（`LocalTransit`、`backend/src/routes/localTransit.ts`、画面は `frontend/src/components/LocalTransitManager.tsx`）。

- スクショ・写真・PDF（15MBまで）を付けて、タイトルと要点を書きます。「AIで読み取る」を押すと、Claude が資料から旅行者向けの要点（運行日・時間・主な乗り場・運賃・予約方法など）の下書きを作ります（`backend/src/services/transitReader.ts`。AIの1回分。資料にないことは書かない指示）。下書きは必ず確認してから公開する作りで、公開後は「資料をAIで読み取り、提供元が確認した内容です」と表示します
- 表示先は「特定の場所」か「すべての場所」。その場所のアクセスページ（`/reels/:id/access`）と自治体ページの「アクセス方法」タブに、提供元・更新日・掲載期限・出典のリンク・元の資料（画像はそのまま、PDFは「PDFを開く」）と一緒に出ます（`frontend/src/components/LocalTransitList.tsx`）。掲載期限を過ぎたものは出ません
- 「AIに旅を相談」でも使われます。AIは投稿と一緒にその場所の交通情報を受け取り、「車なしで」「バスで」などと聞かれたときに、書いてある範囲で案内します。答えのカードには「地元の交通情報あり」が付き、押すとアクセスページのその部分に移ります
- 旅行者は「翻訳を見る」で自分の言語に翻訳できます（AIがあればサーバーで翻訳・1日キャッシュ、なければ端末内のAI）
- 企業は自分の投稿の場所にだけ付けられます（自治体は自分の市町村の場所すべて）。1アカウント30件まで

### 写真・動画の提供（旅行者 → 自治体）

旅行者は自治体のページの「写真・動画を提供する」から、自分で撮った写真・動画をその自治体に送れます（`POST /api/submissions`、`Submission` テーブル、画面は `frontend/src/components/SubmitMediaSheet.tsx`）。「自分で撮影したもので、投稿・紹介に使うことに同意する（人が写っている場合はその人の了解を得ている）」への同意が必要で、投稿されるときに名前を載せるか匿名にするかを選べます。写真は送る前に端末で縮小して位置情報などの付属データを消し、撮影場所・日時だけを先に読み取ります。審査待ちは1つの自治体に20件までで、審査中ならマイページから取り下げられます。

自治体は管理画面の「提供素材」タブ（`frontend/src/components/SubmissionInbox.tsx`、`GET /api/submissions/inbox`）で、届いた写真・動画を見て「承認する」か「見送る」（理由を書くと提供者に表示）を選びます。**承認すると提供者に100ポイント**（`POINTS_PER_SUBMISSION`、`backend/src/lib/points.ts`。ほかのポイントと同じく試作で、まだ使い道はありません）。承認した素材は「この素材で投稿する」で自治体の投稿にできます（`POST /api/reels` に `submissionId`）。動画はそのまま使い（再アップロード不要）、写真は自治体の端末でゆっくりズームする6秒の縦長動画（720×1280）に変換してから投稿します（`frontend/src/lib/photoToVideo.ts`、Canvas と MediaRecorder。サーバー側の動画変換は不要）。投稿には「提供：◯◯さん」（匿名希望なら「旅行者の提供」）と表示されます（投稿の `contributedBy`）。提供者には、承認・見送りをプッシュ通知で、投稿されたことをお知らせとプッシュ通知で伝えます。マイページの「提供した写真・動画」で、審査中・承認（+100pt）・投稿されました・見送り（理由）が分かります。自治体には提供者の名前だけを見せ、メールアドレスは見せません。審査中のファイルもアップロード先のURLは推測できない名前ですが、公開の保存場所に置かれる点はほかのアップロードと同じです

### ポイント・クーポン・AIチケット

ためたポイント（現地スタンプ20pt・移動時間の記録10pt・写真/動画の提供が承認されて100pt）は「ポイント・クーポン」（`/points`、`frontend/src/pages/PointsPage.tsx`、メニューとマイページのポイント欄から）で使えます。残高は「獲得 − 使用」をその都度計算します（`backend/src/lib/points.ts`）。交換は、先に記録を書いてから同じ処理の中で残高・在庫・1人あたりの上限を確かめ、足りなければ取り消すので、同時に押しても使い過ぎになりません。

- **クーポン**：自治体と、その自治体の企業アカウント（飲食店・宿・お店など）が、管理画面の「クーポン」で出せます（`Coupon`、`POST /api/coupons`、画面は `frontend/src/components/CouponManager.tsx`）。名前・内容・使い方/条件・必要ポイント（10以上）・配る枚数・1人あたりの枚数・有効期限を決め、いつでも配布を止められます。旅行者はポイントと交換すると（`POST /api/coupons/:id/redeem`）、「ABCD-EFGH」のようなクーポンコードとQRコードが「持っているクーポン」に入ります。お店では、コードかQRを見せてもらうか、旅行者がお店の人の前で「このクーポンを使う」を押します（1回だけ）。お店側は管理画面の「クーポンの確認」で、「カメラでQRを読み取る」（ブラウザの BarcodeDetector。Android・Mac の Chrome など。ライブラリ不要で画像はどこにも送りません。`frontend/src/components/QrScanner.tsx`）か、コードを入力すると、本物か・使用済みかと持ち主の名前（メールアドレスは出しません）が分かり、「使用済みにする」を押せます（`GET/POST /api/coupons/verify/:code`。自分のクーポンのコードだけ）。交換数・使用数も見られます。自治体のページには、その自治体とお店のクーポンが並びます。交換したポイントは戻りません。期限まで3日を切った未使用のクーポンは、持ち主に1回だけプッシュ通知で知らせます（日本時間9〜21時のあいだ。`backend/src/lib/couponReminders.ts`、10分ごとに確認）
- **AIの回数と料金**：AIに旅を相談・写真で探す・AIでプランを作るは1回で「1回分」、**AIで旅をつくる（しおりの自動作成）は1回で「5回分」**です（`AI_FEATURE_UNITS`、`backend/src/lib/aiQuota.ts`）。ログインしていれば**月30回分まで無料（1日10回分まで、日本時間の毎月1日に戻る）**、それ以上は1回分につきAIチケット1枚。チケットはポイントで交換します（10枚=50pt、30枚=120pt、`POST /api/points/ai-tickets`。期限なし）。ログインしていない人は1日3回分まで（通信元ごと）。使い切ると「AIチケットと交換」への案内が出て、「AIで旅をつくる」の画面には1回で5回分使うことと残りの回数を出します。数えるのは実際にAI（Claude）を使ったときだけで、翻訳は数えません
- **赤字にしないための上限**：アプリ全体のAIの予算を、その日・その月に実際に使ったトークンから計算した料金の見積もりで管理し、超えたら次の日・月まで、相談はキーワード検索、プランは距離順、旅づくりはキーワードで組み立てる方式に自動で切り替えます（写真で探すは「混み合っています」と表示）。そのときは利用者の回数に数えません。予算は `AI_MONTHLY_BUDGET_USD`（標準 300ドル）と `AI_DAILY_BUDGET_USD`（標準はその1/15）で設定します。料金の見積もりは定価からの概算（`backend/src/services/claude.ts`）なので、Anthropicの管理画面でも月の利用上限を必ず設定してください
- **費用を抑える工夫**：AIは標準で Claude Sonnet 5.5（Opus 5.5の半額）を使い（`CLAUDE_MODEL` で変更可）、毎回ほぼ同じ「投稿の一覧」はプロンプトキャッシュに載せて、2回目以降はその部分の料金を約1/10にしています
- **利用の記録とレポート**：AIを使うたびに、機能・回数分・使ったトークン（キャッシュ読み込み/書き込みを含む）・料金の見積もりを記録し（`AiUsage`）、`npm run ai:report`（`backend` で実行、`-- 2026-11` で月を指定）で月ごと・機能ごとの回数、トークン、キャッシュの効き具合、料金（ドルと円、`USD_JPY` で為替を指定、標準150円）、1回あたりの料金、利用者数を見られます。無料の回数や値段は、この実数を見て調整する想定です

### しおりを共有する・何日かの旅

- しおりの「しおりを共有」で、同行者に送れる閲覧専用リンク（`/trip/:token`）を作り、スマホの共有メニュー（LINEなど）を開きます。出発地点（自宅などのことが多い）は共有先には表示しません。共有を受けた人は、気になる場所を1つずつ、または「まとめてしおりに追加」で自分の旅を選んで（または新しく作って）入れられます（未ログインならログイン後に戻ってきます）。共有は旅ごとです。「共有を停止」でリンクはすぐ無効になります（`POST/DELETE /api/me/trips/:id/share`、`GET /api/trips/:token`。表示のたびに区間の移動時間を計算するため、1IPあたり10分60回まで）。リンクのプレビューは「◯◯さんの「京都 2泊3日」（4か所）」と場所名になります
- 宿（カテゴリ「宿」）が最後以外にあると、そこで1泊する扱いになり、翌朝の出発時刻からまた続きます（最低6時間は休む計算）。しおりには「1日目」「2日目」の区切りが入り、時刻は「翌08:00」「3日目 09:00」のように表示されます（`frontend/src/lib/itineraryTimeline.ts`）

### 旅行中モード

しおりの「今日この旅をはじめる」を押すと、旅行中は「いま：松本城（あと25分で出発）」「移動中：次は河童橋（あと12分で到着予定）」のように、計画上いまどこにいるはずかを表示し、その場所をリストで強調します。遅れているときは「＋15分遅れ」で残りの予定をずらせます。時計だけで動くので電波がなくても使えます（`frontend/src/lib/liveTrip.ts`。状態は端末内に保存）。

### 見頃（いちばん良い季節）

自治体・企業は投稿・編集のときに「見頃の月」（任意・複数）を選べます（`Reel.bestMonths`）。フィードの「今が見頃」タブ・地図の「今が見頃」で、今月（日本時間）が見頃の投稿だけを表示します（`GET /api/reels?season=now`）。投稿には「今が見頃」または「見頃 5月–6月・10月」と表示されます。AIコンシェルジュも見頃を読み、「秋に行きたい」「4月」のような相談に見頃の合う投稿を選びます（キーワードモードでも季節・月の言葉を理解します）

### コンパスで向かう

スポットのアクセス画面の「コンパスで向かう」で、目的地の方向を指す矢印と残りの距離（直線）を表示します。スマホの向きに合わせて矢印が回り、40m以内で「到着！」になります。コンパスのない端末では北が上の表示になります。道順の案内ではないため、画面に「直線距離と方角です」と明記しています（`frontend/src/components/WalkCompass.tsx`）

### いま見ている人数

スポットのアクセス画面に、そのページをいま開いている人が自分のほかにもいると「いま3人が見ています」と表示し、人が来たり去ったりすると即座に変わります（Server-Sent Events、`GET /api/reels/:id/live`、`backend/src/lib/presence.ts`）。送るのは人数だけで、誰が見ているかは扱いません。タブごとに1人と数え、裏に回ったタブは数えません。人数はサーバーのメモリ上で数えるため、サーバーが1台の構成（今のRender）を前提にしています。同時接続は全体で2000本まで。

### 新しい投稿をリアルタイムに表示

フィードを開いている間に自治体・企業が投稿すると、再読み込みしなくても上に「↑ 新しい投稿が1件」が出て、押すと先頭に表示されます（Server-Sent Events、`GET /api/reels/feed/live`）。裏に回ったタブは接続を切ります。

### 3Dで巡る

しおり（共有されたしおりも）の「3Dで巡る」で、傾けた3D地図の上をルートに沿って空から順に飛び、各スポットの周りをゆっくり回りながら動画と到着・出発時刻を表示します。一時停止・前後の移動ができ、動きを減らす設定の端末では飛ばずに切り替えます。地図が読み込めなくても、カードの再生は止まりません（`frontend/src/components/TripFlyover.tsx`）

### 音声ガイド

スポットのアクセス画面の「音声ガイドを聞く」で、場所の名前・所在地・見頃・投稿文を端末の音声合成で読み上げます（声の生成は端末内で行い、どこにも送りません。`frontend/src/components/AudioGuide.tsx`）。英語・中国語・韓国語で使っている場合は、AIの翻訳が使えればその言語で読み、使えないときは「日本語で読み上げます」と表示して元の日本語を日本語の声で読みます。

### スタンプ帳を画像でシェア

マイページの「画像でシェア」で、ジャジバのロゴ・スタンプ数・訪れた都道府県数・最近のスタンプ（最大9個）を描いた縦長画像（1080×1920、ストーリー向け）を作り、スマホでは共有メニュー、パソコンではダウンロードになります（`frontend/src/lib/stampCard.ts`）

### 端末内のAIで翻訳

ANTHROPIC_API_KEY が設定されていないときでも、Chrome に組み込まれた翻訳AI（Translator API・Language Detector API）が使える端末では、投稿の説明文とコメントの「翻訳を見る」が使えます（`frontend/src/lib/onDeviceTranslate.ts`、`frontend/src/lib/useTranslatable.ts`）。翻訳は端末の中で行い、文章はどこにも送りません。初めての言語の組み合わせでは翻訳モデルのダウンロードがあり、その間は「翻訳モデルを準備中… 30%」と表示します。コメントは書かれた言語を端末で判定し、表示中の言語と同じなら「表示中の言語と同じです」と出します。翻訳した文には「端末内のAIで翻訳（文章は送信していません）」と表示し、Claude の翻訳（キー設定時はこちらを優先）と区別します。対応していないブラウザでは、これまでどおりボタンを出しません

### みんなの声をまとめる（端末内のAI）

コメントが4件以上ある投稿では、コメント欄の上に「みんなの声をまとめる」が出て、ブラウザに入っているAI（Chrome の Summarizer API）がコメントを短い箇条書きにまとめます（`frontend/src/components/CommentSummary.tsx`、`frontend/src/lib/onDeviceSummarize.ts`）。要約は端末の中で行い、コメントをどこにも送らず、APIキーも料金も要りません。初めて使うときはAIの準備（ダウンロード）に少し時間がかかり、進み具合を表示します。日本語・英語で書き、中国語・韓国語の画面では英語で要約してから端末内で翻訳します。非表示にされたコメントは使いません。要約には「端末のAIによる要約です」と表示します。対応していないブラウザではボタン自体が出ません

### 端末のAIで文章を整える（自治体・お店向け）

投稿や投稿の編集で説明文を10文字以上書くと、その下に「端末のAIで文章を整える」が出ます（Chrome の Rewriter API、`frontend/src/components/CaptionAssist.tsx`・`frontend/src/lib/onDeviceRewrite.ts`）。「魅力的に」「短く」「丁寧に」から選ぶと、ブラウザに入っているAIが書き直した案を出し、「この文にする」で置き換えます。端末の中で動くので、文はどこにも送られず、APIキーも料金も要りません。書かれている事実は変えず、書かれていない値段・営業時間などを足さないよう指示していますが、AIの提案なので確認してから使うよう表示しています。対応していないブラウザでは出ません

### コメントの翻訳（AI）

コメントにも「翻訳を見る」が出ます。投稿文の翻訳と違い、コメントは何語で書かれていてもアプリの表示言語に訳します（日本語表示なら、外国の旅行者の英語コメントを自治体の担当者が日本語で読めます）。翻訳は `CommentTranslation` に保存して使い回します。通報で非表示になったコメントは、本人と管理する自治体・企業以外は翻訳でも取得できません（`POST /api/reels/:id/comments/:commentId/translation`）。`ANTHROPIC_API_KEY` が未設定のときはボタンを表示しません

### 共有で受け取る・アプリのアイコンのバッジ・すばやい画面切り替え

- **共有で受け取る**：ジャジバをホーム画面に追加（インストール）すると、ほかのアプリの「共有」からジャジバを選べます（Web Share Target。`frontend/public/manifest.webmanifest` の `share_target`、`frontend/public/sw.js`、画面は `frontend/src/pages/SharePage.tsx`）
  - 写真：撮影場所（写真のEXIFの位置情報。端末の中で読み取り、送信しません。`frontend/src/lib/exifGps.ts`）が分かれば、その近く50km以内の投稿を近い順に出します。AIが使えるときは「この写真の雰囲気で探す」（写真で探す）にも進めます。位置情報がない写真（共有時に消すアプリも多い）はそう表示します
  - 地図のリンク：URLに座標（`@36.23,137.97`、`?q=`、`ll=` など）があれば、その地点の近くの投稿を出します。短縮URL（maps.app.goo.gl など）は座標が分からないため、文字の部分で検索します
  - 文字：そのまま検索（`/search?q=`）になります
  - 受け取った内容は端末のキャッシュに一時的に置き、表示したら消します。サービスワーカーがまだ動いていないときは、何も受け取れなかった旨を表示します
- **アイコンのバッジ**：未読のお知らせの数をホーム画面のアイコンに表示します（Badging API）。アプリを閉じていてもプッシュ通知が届いたら印を付けます
- **すばやい画面切り替え**：ホームを表示し終えて端末が空いているときに、下のタブ（リール・しおり・マイページ・検索）の画面を1つずつ先に読み込んでおきます。地図は大きいので開いたときだけ。データセーバー（端末・アプリ）や遅い回線では先読みしません。ホーム画面のアイコンの長押しメニューに「ARで探す」を追加しました

### 旅の振り返り

マイページの「2026年の旅を振り返る」（`/recap`、`?year=2025` で過去の年も。`frontend/src/pages/RecapPage.tsx`、`GET /api/me/recap`、`backend/src/routes/recap.ts`）で、その年のジャジバでの旅を、ストーリーのような全画面スライドで見られます（右をタップで次、左で前、長押しで一時停止、6秒で自動で進む）。

- 内容：今年のタイプ（いちばん多く保存・訪問したジャンルから「絶景ハンター」「歴史さんぽ派」「ご当地グルメ通」など）、しおりに保存した場所の数と都道府県、現地で押したスタンプ、いちばん気になった町とジャンル、月ごとの保存・いいね・スタンプの数といちばん多かった月、最後にまとめ
- 数えるのは本人の記録（旅に入れた投稿・スタンプ・いいね・コメント・フォロー）だけで、年は日本時間で区切ります。記録がない年は「まだ記録がありません」と出し、数字を作りません
- まとめはストーリーサイズ（1080×1920）の画像にしてシェア・保存できます（ロゴは提供されたまま）

### 旅のアルバム

しおりの「旅のアルバム」に、旅のメンバーが写真を追加できます（複数まとめて。`TripPhoto`、`POST/DELETE /api/me/trips/:id/photos`、画面は `frontend/src/components/TripAlbum.tsx`）。

- 元の写真の撮影場所・撮影日時（EXIF）を端末の中で読み取り、しおりの場所から2km以内なら「松本城」「上高地 河童橋」のようにその場所の写真としてまとめます（それ以外は「その他の写真」）。写真は端末で長辺1600pxのJPEGに縮めてから送るため、写真ファイル自体には位置情報などのメタデータが残りません。撮影場所の座標はアルバムの振り分けにだけ使い、メンバーにも座標そのものは見せません
- 見られるのは旅のメンバーだけで、全画面表示で左右に切り替えられます。削除できるのは追加した人と旅を作った人です（削除するとファイルも消えます）。1つの旅に500枚まで
- 注意：写真ファイルの保存先は、推測できないランダムな名前の `/uploads/...` です。アプリ上はメンバーにしか表示しませんが、URLそのものを知っている人は開けます（ログイン付きの配信にはしていません）。Render の無料プランではディスクが再起動で消えるため、本番運用では永続ストレージ（S3など）が必要です

### 出発地点を全国どこでも

アクセスプランナー・投稿の「行き方」・しおりの出発地点に、全国の駅・市区町村・住所を入力できます。Google Maps のキーがなくても場所を特定します（`backend/src/services/placeLookup.ts`）。結果には「出発地点を『大阪駅（大阪府）』（駅の位置）として計算しています」のように、何として計算したかを表示します。

- **駅**：約9,000駅（「東京駅」「ＪＲ松本駅」「新宿」など。同じ名前の駅は「広島県府中駅」のように都道府県を付けると選べ、付けないときは路線の多い駅）。出典：国土数値情報「鉄道データ（N02）」令和6年（国土交通省）を加工して作成（[antfu/mlit-json](https://github.com/antfu/mlit-json) 経由）
- **市区町村・区**：全国1,916（「松本」「長野県松本市」「大阪市北区」）。役所・役場の位置で計算します。都道府県名だけなら県庁所在地の役所の位置。出典：[code4fukui/localgovjp](https://github.com/code4fukui/localgovjp)（CC0）
- **住所**：市区町村より下（「大阪市北区梅田1丁目」「渋谷区道玄坂2-1」）は、その町・丁目の代表点で計算します。出典：Geolonia 住所データ（CC BY 4.0）。市区町村ごとのデータを必要なときに取得して1日キャッシュします（取得先は `TOWN_DATA_URL` で変更可。取れないときは市区町村の位置で計算）
- データは `backend/data/places.json`（約700KB）に同梱。Google Maps のキーがあるときは Google の住所検索を先に使い、見つからなければ同梱データを使います。自治体が設定する「起点駅」も、キーなしで駅の位置を設定できるようになりました
- 見つからない名前（例：「宇宙ステーション」）は、これまでどおり名前から推定した仮の結果になり、そう表示します
- **所要時間について**：出発地点が分かっても、Google Maps のキーがない間の所要時間は直線距離からの概算（仮データ）です。キーを設定すると徒歩・車は実際のルートの時間になります。電車・バスの実際の時刻・乗換・運賃は、Google の API では日本の情報が提供されていないため、駅すぱあと・NAVITIME などの有料APIとの契約が必要です

### 移動中の情報（乗る便・移動中モード・乗換案内）

バス・電車・飛行機などで移動している間に使う情報です。

- **乗る便**：しおりの「乗る便（飛行機・電車・バスなど）」に、予約した便を登録できます（種類・便名/列車名・会社・出発地/到着地・出発/到着日時・番線/ゲート/のりば・座席・予約番号・メモ。`TripTransport`、`POST/PUT/DELETE /api/me/trips/:id/transports`、画面は `frontend/src/components/TripTransports.tsx`）。旅のメンバー全員で編集でき、変更はみんなのしおりにすぐ反映されます。出発1時間前から「あと19分で出発」、乗車中は「移動中」と出ます。共有リンク（閲覧専用）には便名・時刻・のりばだけを出し、座席・予約番号・メモは出しません。しおりと一緒に端末に保存されるので、電波のない機内でも見られます
- **移動中モード**：便ごとの全画面表示（`frontend/src/components/TransitModeView.tsx`）。出発前は「出発まで」、乗車中は進み具合のバーと「◯◯到着まで 3:52」を大きく表示し、のりば・座席・予約番号も出します。「到着5分前に知らせる」をオンにすると、到着の約5分前に振動と通知（許可した場合）と画面の表示で知らせます。開いている間は画面が消えません（Screen Wake Lock）。パソコンの Chrome などでは「小窓で表示」で、出発・到着までのカウントダウンとのりばを、ほかのアプリの上に浮かぶ小さな窓に出せます（Document Picture-in-Picture。移動中モードを閉じると小窓も閉じます）。複数の便は左右で切り替えられます
- **出発・到着のプッシュ通知**：出発の約30分前（「あずさ5号 まもなく出発（約20分後）」「新宿 09:00発・9番線」）と、到着の約5分前（「まもなく松本に到着（約4分）」）に、旅のメンバー全員の通知をオンにしている端末へ届きます。アプリを閉じていても届きます（`backend/src/lib/transportAlerts.ts`、30秒ごとに確認。各通知は1回だけで、時刻を変更すると新しい時刻でもう一度送ります。サーバーが止まっていて2分以上遅れた出発通知は送りません）。Renderの無料プランではしばらくアクセスがないとサーバーが休止するため、その間の通知は届きません
- **時刻は登録した予定の時刻です**。ジャジバは時刻表・遅延・運航状況を自動で取得しません（Google の経路APIは日本の電車・バスの情報を返さず、時刻表や航空便のAPIは有料のため）。そのため各便に「運行状況」リンクを付けています（電車：Yahoo!路線情報の運行情報、飛行機・バス：便名で検索）
- **乗換案内**：しおりの各区間（徒歩以外）に「Googleマップ」「Yahoo!乗換案内」のリンクを付け、出発地と到着地を入れた状態で開きます（`frontend/src/lib/transitLinks.ts`）。Google マップのアプリでは日本の電車・バスの経路・時刻・番線を確認できます。ジャジバ内の区間の所要時間は、これまでどおり概算（Google Maps 設定時は徒歩・車の実測）です
- **区間ごとの行き方**：しおりの各区間（出発地点から1か所目、そのあと各スポットの間）に「行き方を書く」があり、電車・バス・車・タクシー・徒歩・自転車・飛行機・船・その他から、その区間の行き方をいくつでも書き出して比べられます（1区間10件まで。名前・所要時間・料金・メモ、電車/バス/飛行機/船は乗る便（便名・発着地・発着時刻・番線）も。`TripLegOption`、`POST/PUT/DELETE /api/me/trips/:id/leg-options`、画面は `frontend/src/components/LegOptions.tsx`）。1区間に1つ「これで行く」を選ぶと、その時間（書いた所要時間、なければ1本目の出発から最後の到着まで）がしおりの時刻に反映され、区間の表示が「電車で1時間45分（決定）」になります。選んだ便が出発予定より早いときは「滞在を短くすると間に合います」、遅いときは「◯分の待ち時間があります」と出ます。「これで行く」にした行き方の便だけが、乗る便の一覧・移動中モード・出発/到着の通知・共有リンクに使われます（ほかの候補の便は通知しません）。決めた行き方の料金は「交通費 合計」として最後に出します。共有リンクには決めた行き方だけを、メモ・座席・予約番号なしで出します。スポットをしおりから外すと、その区間の行き方も消えます
- **乗換案内の結果を貼り付け**：行き方や乗る便の入力画面で、乗換案内アプリ・サイトで「ルートをコピー」した文を「コピーした内容を貼り付け」（または入力欄に貼り付け）すると、駅名・発着時刻・路線名・番線を読み取って入れます（`frontend/src/lib/transitPaste.ts`。Yahoo!乗換案内・ジョルダン・NAVITIME などの「■駅名」「｜路線」形式や「東京 08:52発 → 長野 10:24着」のような文に対応。日付が無ければ旅行日、深夜をまたぐ時刻は翌日にします）。乗換がある場合は乗車ごとに分けて入ります（乗る便の画面では「2本まとめて保存」、`POST /api/me/trips/:id/transports/batch`）。区間に結びつけずに登録した乗る便は、同じ区間（同じ2地点、またはその区間の時間帯に出発）の下に「保存済み 11:56発→12:53着 ◯◯」と出ます
- **乗換案内アプリから「共有」→ ジャジバ**：ホーム画面に追加したジャジバには、乗換案内アプリの共有メニューからルートを送れます。共有画面でルートを読み取り、保存先の旅（日付の近い旅が最初に選ばれます）を選んで保存します。読み取りは端末内で行い、文はどこにも送りません。読み取れない項目は空欄のままにし、勝手に補いません

### 予約明細（しおりの「予約」）

宿・お店・体験の予約を、しおりに入れておけます（`TripReservation`、`POST/PUT/DELETE /api/me/trips/:id/reservations`、画面は `frontend/src/components/TripReservations.tsx`）。名前・チェックイン/チェックアウト（または予約日時）・予約番号・人数・プラン・料金・支払い（支払い済み/現地払い）・予約したところ・住所・電話・予約内容のページ・メモ・しおりの場所を記録し、カードからは予約番号のコピー、地図、電話、予約ページを開けます。オフラインでも見られます（フロントでの提示に）。

- **予約確認メールを貼り付け**：「読み取る」は端末の中だけで、楽天トラベル・じゃらん・一休・Booking.com・食べログなどのよくある書き方（予約番号・施設名・チェックイン・泊数・人数・合計金額…）を読み取ります（`frontend/src/lib/reservationPaste.ts`、何も送りません）。読み取れないときは「AIで読み取る」（AIの1回分、`backend/src/services/reservationReader.ts`）。どちらも入力欄を埋めるだけで、確認してから保存します
- 予約番号・料金・支払い・メモ・予約ページは旅のメンバーだけ。共有リンクでは名前・日時・住所・電話だけを出します
- **予約したその瞬間にしおりへ**：楽天トラベルは予約の完了をジャジバに知らせない（予約の通知や照会のAPIがない）ため、「宿を探す・予約」で「予約へ」を押した時点で、宿・日程・人数・プラン・料金をいまのしおりに「手続き中」として入れます（`frontend/src/lib/pendingBooking.ts`）。ジャジバに戻ると「予約できましたか？」と聞き（予約番号も入れられる）、「予約できた」で予約済みに、「やめた」で消えます（`PendingBookingPrompt.tsx`、`PATCH /api/me/trips/:id/reservations/:id`）。手続き中のものは共有リンクには出ません
- **確認メールを共有するだけ**：メールアプリの「共有」→ジャジバ（ホーム画面に追加したアプリ）で、予約確認メールを読み取って、しおりを選んで入れられます（`SharePage.tsx`）。同じ宿・同じ日の「手続き中」があれば、新しく作らずにそこへ予約番号などを入れます

### 天気予報つきのしおり

しおりに旅行日を入れると、各日の最初のスポットの天気（晴れ・雨など、最高/最低気温、降水確率）を「1日目」「2日目」ごとに表示します（16日先まで。`frontend/src/components/TripWeather.tsx`、`POST /api/weather`、`backend/src/services/weather.ts`）。雨・雪・雷の予報か降水確率60%以上の日には「◯日目は雨の予報です」と出し、その日の最初のスポットから25km以内で屋内で楽しめそうな投稿（飲食店と、説明文や場所名に「美術館」「博物館」「温泉」「工房」「カフェ」などとある投稿。`GET /api/weather/indoor`）を、選んだ理由つきで最大3件提案します。「＋」でその日の最後（宿の前）に入ります。

- 天気は Open-Meteo（キー不要、データは CC BY 4.0。画面に出典を表示）から取得し、サーバーで約10km四方ごとに1時間キャッシュします。**Open-Meteo の無料APIは非商用向けです。** 商用で公開するときは Open-Meteo の有料プランに申し込み、`OPEN_METEO_API_KEY` を設定してください（有料用の接続先に切り替わります）
- 予報が取れないときや範囲外の日は、天気をでっち上げずに「予報なし」「天気予報を取得できませんでした」と表示します。オフライン表示中は出しません

### ARで探す

地図の「AR」ボタン（`/ar`、`frontend/src/pages/ArPage.tsx`）で、スマホをかざすとカメラの映像の上に、その方向にある投稿スポットが「松本城 1.0km」のように浮かびます。近い場所ほど大きく下に、遠い場所ほど小さく上に出て、重なるときは上にずらします。スマホを上に傾けると、窓から見るように全体が下へ動きます。タップすると、場所・方角と直線距離・「行き方」「しおり」のカードが出ます。画面の外にある場所は左右の「＜ 2」「3 ＞」と、左下のレーダー（真ん中が自分、扇形がカメラの向き）で分かります。表示範囲は 1・5・30・100km から選べ、最初は3か所以上が入るいちばん狭い範囲になります。

- 方角は端末の向きセンサーから、背面カメラが向いている方角を計算します（Androidは W3C のコンパス方位の式、iPhoneは `webkitCompassHeading`。`frontend/src/lib/arProjection.ts`、`frontend/src/lib/useArSensors.ts`）。iPhoneでは「カメラを起動する」を押したときに向きセンサーの許可を求めます
- コンパスがない端末（多くのパソコン）では、左右にドラッグして見回せます。カメラが使えない場合は背景だけで表示し、そう明記します。位置の精度が低いとき（100m超）も表示します
- カメラ映像・位置・向きは端末の中だけで使い、録画もサーバーへの送信もしません。距離と方角は直線で、道順は「行き方」で確認します

### パスキーでログイン

パスワードの代わりに、端末の顔認証・指紋・画面ロック（Face ID、Touch ID、Windows Hello、Androidの指紋など）でログインできます（WebAuthn。`backend/src/routes/passkeys.ts`、`frontend/src/lib/passkeys.ts`、ライブラリは SimpleWebAuthn）。顔や指紋は端末の中だけで確認され、サーバーには公開鍵と署名だけが届きます。

- 作り方：パスワードでログインした直後に「次回から顔認証・指紋でログインしませんか？」と1回だけ案内します（「あとで」はその端末で記憶）。設定の「パスキー」からも作成・削除でき、端末名・ほかの端末と同期しているか・最後に使った日時が出ます（1人10個まで）
- ログイン：ログイン画面の「パスキーでログイン」か、メール欄を押したときに出る候補からパスキーを選ぶだけで、メールアドレスもパスワードも入力せずにログインできます（discoverable credential と conditional UI）
- 削除したパスキーは、ブラウザ・パスワード管理にも「もう使えない」と伝えて候補から消してもらいます（WebAuthn Signal API。対応ブラウザのみ）
- サイトの識別（RP ID）は開いているページのドメインから決まるため、localhost でも公開ドメインでも設定不要です。ドメインを変える（例：jaziba.jp へ移る）と、古いドメインで作ったパスキーは使えなくなります（パスワードでのログインはそのまま使えます）。`WEBAUTHN_ORIGIN`（例：`https://jaziba.jp`）で固定もできます
- 確認待ちのチャレンジはサーバーのメモリに5分だけ置きます（1台構成が前提）。開始は10分60回まで、失敗はパスワードと同じく15分10回まで

### プッシュ通知

設定の「プッシュ通知（この端末）」をオンにすると、お知らせ（フォロー中の新しい投稿、いいね・コメント）がアプリを閉じていても端末に届きます（Web Push。通知の文言は端末の表示言語）。iPhoneでは、Safariの「ホーム画面に追加」で入れたアプリで使えます。ログアウトするとその端末には届かなくなります。
- 送信用の鍵（VAPID）は、環境変数 `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` があればそれを使い、なければ初回に自動で作ってデータベース（`AppSetting`）に保存します。**データベースが作り直されると鍵も変わり、それまでのプッシュ登録は使えなくなる**ので、本番では `npx web-push generate-vapid-keys` で作った鍵をRenderの Environment に設定しておくのがおすすめです（任意で `VAPID_SUBJECT` に連絡先 `mailto:...` または `https://...`）
- 届かなくなった端末（プッシュサービスが404/410を返したもの）は自動で登録を消します

### アクセスプランナー（自治体プロフィールの「アクセス方法」タブ）

自治体プロフィールページの「アクセス方法」タブから、訪問者が自分の出発地点（駅名など）を自由に入力し、その自治体の起点駅までの**所要時間・移動手段・概算運賃**を確認できます（`GET /api/municipalities/:id/access-plan`）。既存の「リールごとの自動MaaS表示」と違い、こちらは訪問者がボタンを押した時だけAPIを呼ぶ一度きりの操作なので、閲覧のたびに自動発生する既存のDirections API呼び出しとは別枠で、コスト面のリスクは低めです。

運賃は実際の運賃データを取得しているわけではなく、距離に応じた**簡易な概算**（`maasProvider.ts` の `estimateFareYen`：¥150基礎運賃＋距離に応じた1kmあたりの単価）です。画面上にも「※運賃は概算です」と明記しています。正確な運賃が必要な場合も、上記の乗換案内特化APIへの切り替えが前提になります。

各リールの再生画面にも同様の「アクセス」ボタンがあり、こちらは自治体の起点駅ではなく**その投稿の場所そのもの**を目的地として計算します（`GET /api/reels/:id/access-plan`）。

どちらの画面でも出発日時（`<input type="datetime-local">`）を指定でき、車移動の場合はGoogle Directions APIの`departure_time`パラメータにより**実際の予測交通状況を反映した所要時間**が得られます。ただし、この機能は電車・バスの実際の発着時刻表とは連動していません（本アプリはそのデータを持っていません）。到着予定時刻は、あくまで「指定した出発日時＋徒歩/車移動の所要時間」の計算値であり、画面にも常にその旨のディスクレーマーを表示しています。実際の乗換時刻表が必要な場合は、既出の駅すぱあと／NAVITIME等への切り替えが前提です。

リールのアクセスページでは電車・バス・車・タクシー・徒歩の5通りを並べて比較でき（`frontend/src/lib/accessModeEstimate.ts`）、各カードの詳細を開くと経路プレビュー画像も表示されます（`GET /api/reels/:id/access-map`）。この画像はGoogle Directions APIが返す実際の道路上のルート（polyline）をStatic Maps API経由で描画したものですが、Directionsが使えなかった場合は出発地点〜目的地を結ぶ直線にフォールバックします（実際の道なりではない点に注意）。Static Maps APIが未設定・呼び出し失敗の場合は、画面側で簡易な概略図（点線のプレースホルダー）に自動で切り替わります。5モードのうち実際にAPIで取得できるのは徒歩または車のいずれか1つだけなので、電車・バス・タクシーの時間や運賃は距離ベースの概算です（画面にもその旨明記）。

## 投稿インサイト（自治体・企業向け）

自治体・企業アカウントは `/insights` から、自分（自治体の場合は紐づく企業の投稿も含む）の投稿の再生数・いいね数・コメント数と、カテゴリ別・投稿別の内訳を確認できます。

さらに、Instagramの「オーディエンス」に相当する視聴者の**国籍・年代別の内訳**も表示します。これは `ReelView` テーブル（`backend/prisma/schema.prisma`）に記録される閲覧ログと、`User.nationality` / `User.birthYear`（登録時またはSettingsから**任意**で入力）を突き合わせて集計したものです（`GET /api/reels/mine/demographics`）。ログアウト中の視聴や、国籍・生まれた年を登録していないアカウントによる視聴は「不明」として分類されます — Instagramなどと同様、自己申告データがある範囲でしか属性を特定できない設計です。

メールアドレスからは年齢・国籍いずれも推測できないため（ドメインだけでは国籍の判定精度が低すぎる）、新規登録画面では `geoip-lite`（オフラインのIP→国データベース、外部API呼び出し・APIキー不要）でIPアドレスから国籍欄の初期値をおおまかに推定し、プルダウンに仮選択した状態で表示します（`backend/src/services/geoLookup.ts`、`GET /api/auth/suggest-nationality`）。あくまで初期値の提案であり、本人はいつでも変更・未選択にでき、保存もされません。生まれた年はこの方法でも取得できないため、引き続き完全に自己申告です。設定画面のプロフィール欄からも、国籍・生まれた年はいつでも編集できます（一般ユーザーアカウントのみ）。

## しおり（保存した場所をつなぐ旅程）

しおりは**旅ごと**に作ります。旅行者はまず「京都 2泊3日」のような旅（`Trip`）を作り、投稿の保存ボタンを押すと出る「どの旅に入れる？」で入れる旅を選びます（複数の旅に入れることも、その場で新しい旅を作ることもできます。`frontend/src/components/TripPickerSheet.tsx`、`backend/src/routes/myTrips.ts`、`/api/me/trips`）。メニューの「しおり」（`/itinerary`）が旅の一覧で、旅を開くと（`/itinerary/:tripId`）その旅のしおりになります。幅の広い画面ではページ右側にもしおりが常時表示され、上のメニューで旅を切り替えられます（`frontend/src/components/ItineraryRail.tsx`。自治体・企業アカウントには表示されません）。旅に入れた投稿をつなぎ、時刻入りの行程表にします（`GET /api/me/trips/:id/itinerary`）。位置情報を持たない投稿は経路に含められません。

- 旅の名前・旅行日はしおりの上部で変えられ、旅は削除もできます（ほかの旅に入っていない場所は保存も外れます）。「保存済み」かどうかは、どれか1つの旅に入っているかで決まります（`SavedReel` はその目印として旅と連動）
- 以前の「しおり」（旅の機能より前に保存した場所）は、そのままの順番・滞在時間・出発設定・共有リンクで「はじめての旅」に移しました。旅を選ばずに保存したとき（APIで旅を指定しなかったとき）は、最後に使った旅（なければ新しい「はじめての旅」）に入ります
- **並び替え・削除**：各スポットの左のつまみ（⋮⋮）を押したままドラッグすると、好きな位置に入れ替えられます（指でもマウスでも。落とす位置に赤い線が出ます）。↑↓ボタンでも1つずつ動かせます（`PUT /api/me/trips/:id/order`、`TripItem.position`）。新しく入れた場所は末尾に入ります。×はその旅から外す操作です
- **滞在時間**：スポットごとに滞在時間（0〜240分）を選べます（旅ごとに別。`PATCH /api/me/trips/:id/items/:reelId`、`TripItem.stayMinutes`、初期値60分）
- **出発地点・出発時刻・旅行日**：しおり上部で設定します（`PATCH /api/me/trips/:id`）。出発時刻＋移動時間＋滞在時間を足し合わせて、各スポットの「◯時◯分着 → ◯時◯分発」と最後の場所の出発時刻を表示します（日付をまたぐと「翌」）
- 出発地点から最初のスポットまでの移動時間は、出発地点をジオコーディングできた場合（Google Maps設定時）のみ含めます。位置を特定できない場合は名前ベースの仮データでごまかさず、移動時間を含めていない旨を表示し、出発時刻に最初のスポットへ着く想定で計算します（仮データが数時間ずれると、以降の時刻がすべてずれるため）
- しおりは画面の端に常駐していて、他の画面での保存・保存解除にも追従します（`frontend/src/lib/savesChanged.ts`）。逆に、しおりで外した投稿はフィードなどの保存表示にも反映されます
- **一緒に計画する（共同編集）**：旅の持ち主は、しおりの「一緒に計画する人」→「招待する」で招待リンク（`/join/:token`）を作り、LINEなどで送れます。開いた人はログイン後に「参加する」を押すとメンバーになり、場所の追加・削除・並び替え・滞在時間・旅行日などを一緒に編集できます（旅の削除・共有リンク・招待の管理は持ち主だけ）。誰かが変更すると、開いている全員のしおりにすぐ反映され「◯◯さんがしおりを更新しました」と出ます。いま同じしおりを開いている人は「いま◯◯さんも見ています」と緑の点で表示します（Server-Sent Events。`backend/src/lib/tripLive.ts`、`GET /api/trips/live/:ticket`。ブラウザの EventSource はログイン情報を送れないため、`POST /api/me/trips/:id/live-ticket` で1分だけ使える使い捨ての合言葉を受け取ってからつなぎます）。「招待を停止」でリンクはすぐ無効になり、持ち主はメンバーを外せ、メンバーは自分で抜けられます（`POST/DELETE /api/me/trips/:id/invite`、`POST /api/me/trips/join/:token`、`DELETE /api/me/trips/:id/members/:userId`）。招待リンクのプレビューは「◯◯さんから「京都 2泊3日」への招待」になります
- **みんなの現在地**：旅のメンバーが2人以上いると、「一緒に計画する人」に「旅行中、現在地をみんなに共有」が出ます。オンにした人の現在地が、そのしおりのメンバーだけに届き、「上高地 河童橋の近く（約29m）・今」のように、しおりのいちばん近い場所からの距離で表示されます（`POST/DELETE /api/me/trips/:id/location`、`backend/src/lib/tripLive.ts`、`frontend/src/lib/useShareLocation.ts`）。共有はそのページを開いている間だけで、サーバーのメモリにだけ置き、保存しません（10分更新がなければ消えます）。「やめる」・ページを閉じる・旅から抜ける／外されると止まります。送るのは動いたときか30秒ごと（サーバー側でも5秒以内の連続は無視）。共有中は画面が自動で消えないようにします（Screen Wake Lock。対応ブラウザのみ）

区間ごとの移動時間は、既存のアクセスプランナーと同じ`getTransitSuggestion`（`maasProvider.ts`）をそのまま再利用しています。2つの保存済み投稿は互いに位置情報（緯度経度）を持っているため、ジオコーディングなしで直接Directions APIに渡せます。Google Maps未設定時や実データが取得できない場合は仮データにフォールバックし、「仮データ」バッジで明示します。両端の座標が分かっている場合の仮データは、直線距離をもとにした概算です（道のりは直線の約1.4倍と仮定し、2km以内は徒歩4.5km/h、それより遠い場合は徒歩10分＋電車・バス。平均速度は乗り換えや待ち時間込みで、道のり40kmまで約30km/h（普通列車・バス）、150kmまで約55km/h（快速・特急）、それ以上は約110km/h（新幹線・特急）と距離で段階的に変えています）。以前は場所の名前から決まる数値だったため、30mしか離れていない場所の間が50分になることがありました。

「リスト／地図」の切り替えで、保存した場所を線でつないだ簡易図も表示できます（`frontend/src/components/SchematicRouteMap.tsx`）。実際の地図データ（道路・地形）は使用しておらず、各投稿の緯度経度を単純に正規化して配置しただけの模式図です（相対的な位置関係は実座標に基づいていますが、あくまで概略図としてご利用ください）。同じコンポーネントは、リールのアクセス詳細画面（`ReelAccessPage`の「詳しく見る」）でGoogle Static Maps APIの画像が取得できなかった場合のフォールバック表示にも使われています。

## 自治体・企業向け：LIVE（いま見られている投稿）

管理画面の上部に「LIVE いま5人があなたの投稿を見ています」と、いま見られている投稿ごとの人数を表示します（10秒ごとに更新、`GET /api/reels/mine/live`、人数のみ）。地図・フィードでも、いま誰かが見ているスポットは光って人数が出ます（`GET /api/reels/live-counts`）。

## 自治体・企業向け：旅行計画への効果（インサイト）

インサイト画面（`/insights`）に、投稿が実際の旅行計画にどれだけつながっているかを追加しています（`GET /api/reels/mine/trip-planning`）。

- 保存（しおり）数：各投稿を旅行者がブックマークした数。しおりはブックマークから作られるため、「行き先候補に入れた」人数の目安になります。投稿ごとの一覧にも保存数として表示し、保存数順に並べ替えられます
- CSVで保存：投稿ごとの数値（投稿日・場所・説明文・カテゴリ・投稿者・再生数・いいね数・コメント数・保存数・実測の記録数）をCSVでダウンロードできる。Excelで日本語が文字化けしないよう先頭にBOMを付け、投稿者が書いた説明文が `=` などで始まっていてもExcelの数式として実行されないよう無害化している（`frontend/src/lib/csv.ts`）
- 実測の記録数：旅行者が記録した「実際にかかった時間」の件数（⏱）
- 旅行者はどこから来ているか：実測の記録の出発地点と、使った移動手段の内訳。上記のプライバシーのルールにより、2人以上が記録した出発地点だけを表示し、それ以外は件数のみ表示します

## 旅行スタイルにあわせた「おすすめ」

一般ユーザーは設定画面の「旅行スタイル」で、よく一緒に行く人（ひとり／カップル・夫婦／家族・子連れ／友人グループ）、興味のあるカテゴリ、バリアフリー対応・外国語対応を優先するかを設定できます（`User.travelCompanion` ほか、`PUT /api/auth/me`）。設定があると、フィードの「おすすめ」タブ（カテゴリ未選択時）の並び順が変わります（`backend/src/lib/personalize.ts`）。

- 各投稿の「対応・おすすめ相手タグ」とカテゴリを設定と照らし合わせて点数化し、点数の高い順に並べます（同点なら新しい順）。重みはバリアフリー4・外国語対応3・興味のあるカテゴリ3・同行者2で、移動の必要条件（バリアフリー）を好み（カテゴリ）より優先しています。一致しない投稿も非表示にはせず、後ろに並ぶだけです
- 並び順をブラックボックスにしないよう、上位に来た理由をリールの全画面表示に「おすすめ理由：興味のあるカテゴリ（文化）・「家族・子連れ」の旅行向け」のように表示します。フィード上部にも、並び替え中かどうかと設定画面へのリンクを出します
- 並べ替えには候補全体が必要なため、パーソナライズ時は最新100件を1ページで返します（通常時は従来どおり新しい順10件）
- ログインしていない場合・カテゴリタブ選択時・旅行スタイル未設定時は、従来どおり新しい順です。検索画面の「AIレコメンド」（人気度ベース）とは別の仕組みです

## 対応・おすすめ相手タグ

投稿ごとに「バリアフリー対応」「家族・子連れ向け」「カップル向け」「友人グループ向け」「外国語対応」を付けられます（`Reel.travelerTags`、カンマ区切り文字列。値の一覧は `backend/src/types.ts` の `TRAVELER_TAGS`）。自治体・企業が投稿時に選ぶか、ダッシュボードの投稿の「投稿を編集」から後から変更できます（`PUT /api/reels/:id`）。付けたタグはリールの全画面表示とアクセス画面に表示されます。

- 「バリアフリー対応」「外国語対応」は実際の設備・対応状況についての事実の主張なので、編集画面に「確認したうえで設定してください」と注記しています
- デモ用シードには主観的な「誰向けか」のタグ（家族・カップル・友人）だけを入れ、バリアフリー・外国語対応は入れていません（実在施設について未確認の主張をしないため）

## 近くの観光スポット

リールのアクセス画面（`/reels/:id/access`）の下部に、その投稿の近く（半径50km以内）にある他の投稿を近い順に最大6件表示します（`frontend/src/components/NearbySpots.tsx`、`GET /api/reels/:id/nearby`）。投稿した自治体・企業に関係なく、位置情報（緯度経度）を持つすべての投稿が対象です。距離は各投稿の緯度経度からの直線距離（haversine）で、道のりの距離ではありません。上部のカテゴリ（自然・文化・アクティビティー・宿・飲食店）で絞り込めるので、「近くの宿」「近くの飲食店」だけを探すこともできます（`?category=`）。カードをクリックするとその投稿のアクセス画面に移動するので、「1つ見つけた場所 → 近くの別の場所 → そこへの行き方」と続けて調べられます。位置情報を持たない投稿では空表示になります。

自治体の「観光情報」に登録された観光スポットのうち位置（緯度経度）を持つものも、「自治体の観光情報より」として近い順に表示します（カテゴリが無いため「すべて」のときのみ。タップでその自治体のページへ）。スポットの位置は、ダッシュボードの観光情報タブで緯度経度を入力するか、両方空にしておくとスポット名＋自治体名からGoogle Mapsで自動的に探します（`backend/src/lib/locateTourismSpot.ts`。見つからない・未設定のときは推測で埋めず「位置なし」のまま）。デモ用シードでは河童橋のみ座標を持たせ、大正池は確かな座標を確認できなかったため、Google Maps設定時の自動検索に任せています。

その下には、投稿した自治体の「宿情報」「飲食店」の内容と宿の予約サイト検索リンク（プロフィールと同じもの）を表示し、プロフィールへのリンクも置いています（`frontend/src/components/MunicipalityStayInfo.tsx`）。投稿を見つけた旅行者が、自治体のプロフィールを探しに行かなくても宿・飲食店の情報までたどれるようにするためです。

デモ用シードには、この機能が初回起動直後から確認できるよう、松本市の投稿を4件（松本城・上高地 河童橋・五千尺キッチン・上高地帝国ホテル）入れています。動画はいずれも実写素材がないため、場所名を表示するだけのプレースホルダー（`backend/seed-assets/`）です。

## みんなの実測（実際にかかった時間の記録とポイント）

リールのアクセス画面に「実際にかかった時間（みんなの実測）」欄があります（`frontend/src/components/TravelReportSection.tsx`）。実際にその場所へ行った一般ユーザーが、出発地点・移動手段（電車／バス／車／タクシー／徒歩）・かかった時間を記録すると10ポイントもらえます（`POST /api/reels/:id/travel-reports`、一般ユーザーのみ）。

- 記録は「ユーザー × 投稿 × 移動手段」ごとに1件（`TravelTimeReport`、ユニーク制約）。同じ組み合わせで記録し直すと時間が上書きされるだけで、ポイントは増えません（同じ記録の繰り返しでポイントを稼げないようにするため）
- 集まった記録は**出発地点＋移動手段ごと**に平均して表示します（`GET /api/reels/:id/travel-reports`）。出発地点が違うと所要時間は大きく変わるため、全員分をまとめた1つの平均は出しません。出発地点は入力された文字列（前後の空白などを整えたもの）で一致判定するので、「小田原駅」と「小田原」は別の出発地点として扱われます
- アクセスを検索した出発地点と同じ地点からの記録がある場合は、該当する移動手段のカードにも「みんなの実測 平均◯分・◯件」を表示します
- ポイントは記録件数から都度計算しています（`backend/src/lib/points.ts`、残高は保存していません）。マイページで合計を確認できます（`GET /api/auth/me/points`）。**ポイントの使い道（クーポン等）はまだ無く、画面上でも試作である旨を表示しています**
- 記録はユーザーの自己申告で、正確さは検証していません。デモ用シードにも、実際の記録と誤解されないよう実測データは入れていません
- **出発地点のプライバシー**：出発地点は自由入力のため、自宅の住所などが入力される可能性があります。そのため、**2人以上の異なるユーザーが同じ出発地点を記録するまでは、その出発地点を誰にも表示しません**（`backend/src/lib/travelReports.ts` の `MIN_REPORTERS_PER_ORIGIN`）。非表示の記録は件数だけ表示し、記録した本人には「あなたの記録」として常に表示します。入力欄にも、他のユーザーに表示されるので駅名などを入力するよう注記しています。同じルールを自治体向けインサイトにも適用しています

## 不正利用対策（回数制限）

パスワードの総当たりやスパムを防ぐため、IPアドレスごとに回数制限をかけています（`backend/src/middleware/rateLimit.ts`、`express-rate-limit`）。上限を超えると429とメッセージを返します。

- ログイン：失敗が15分に10回まで（成功したログインは数えないため、同じネットワークの他の人の通常利用で締め出されることはない）
- アカウント登録（旅行者・自治体・企業）：1時間に10回まで
- コメント・実測の記録：10分に30回まで
- お問い合わせ：1時間に5回まで
- 共有されたしおりの表示：10分に60回まで
- ライブリアクション：1分に40回まで

カウンターはメモリ上にあるためサーバー再起動でリセットされます（1台構成の前提）。利用者のIPを正しく得るため、`trust proxy` はRenderの前段プロキシ1段分だけを信頼する設定です（`true` にすると、利用者が `X-Forwarded-For` ヘッダーを偽ってIPを詐称し、制限をすり抜けられてしまうため）。CDNなどプロキシが増える場合は環境変数 `TRUST_PROXY_HOPS` で段数を指定してください。

## 多言語対応

i18next / react-i18next を使い、日本語・英語・中国語・韓国語に対応しています（`frontend/src/locales/`）。対応範囲はアプリのUI文言（ボタン・メニュー・フォームラベルなど）のみで、自治体が入力する説明文・投稿キャプション・都道府県名などのユーザー/実体データは翻訳されません。初めて開いたときは、ブラウザの言語設定（英語・中国語・韓国語なら、その言語）で表示します（`frontend/src/lib/detectLanguage.ts`）。設定画面（`/settings`）の「表示言語」から切り替えでき、選択言語は端末のlocalStorageに保存されます。


画面ごとのプログラムは、トップのフィード以外は初めて開いたときに読み込みます（`React.lazy`、`frontend/src/App.tsx`）。翻訳ファイルも日本語だけを最初に読み込み、英語・中国語・韓国語は選んだときに読み込みます（`frontend/src/i18n.ts`）。前回英語などを選んでいた人には、読み込みが終わるまでの一瞬だけ日本語が表示されます。
